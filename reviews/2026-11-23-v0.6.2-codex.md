## Summary

All 1,405 existing tests passed, including the numerical examples. Two distinct parameter sets can nevertheless resolve to one stored solution, a failed recomputation can modify the earlier result, and changing the analytical reference can leave an old error estimate in place. The cases below also expose incorrect numerical output and failures in the analysis utilities.

## What was checked

I read the package entry point, types and constructors, configuration and sweep expansion, parameter parser and hash, persistence and migration, conversion and statistics pipelines, all six example solvers, their shared code, and the hyperbolic preset. I compared behavior with the README, package conventions, data/statistics/configuration documentation and relevant tests. I checked the CI version pin, declarations and generating models, ran the existing Julia suite, and ran the README heat workflow on a small grid with parallel execution and statistics enabled. The 20 whole-file attestations cover the runtime implementation. I used tests, documentation and CI configuration as context. Local execution used Linux, Julia 1.13.4 and two Julia threads. I did not run other Julia versions, downstream frontends or multi-process stress tests locally.

## Findings in the reviewed files

All findings below are open. The case names refer to functions in the [runnable checks](2026-11-23-v0.6.2-codex-evidence/check.jl). The [captured output](2026-11-23-v0.6.2-codex-evidence/output.txt) includes each observed result.

| # | Severity | Where | Observed behavior and suggested correction |
|---|---|---|---|
| 1 | **major** | `src/Serialization.jl:440`, `src/Simulations.jl:244` | A sweep over `Any[1, "1"]` generates one task. Both normalized dictionaries serialize to the same hash input. A solver that branches on the parameter type gives 1 for the integer and 2 for the string. Loading the string case silently returned 1. Give distinct normalized values an unambiguous encoding and verify stored parameters on lookup. Preserve access to existing files with a versioned lookup or migration. See `hash_case`. |
| 2 | **major** | `src/Simulations.jl:282` | The solver receives a shallow copy of its task. Changing `q[:weights][1]` inside the solver also changed the caller’s weights from `[1, 2]` to `[9, 2]`. The cache had no result under the original parameters. Keep an independent snapshot of the requested parameters and isolate mutable values passed to each solver. See `mutation_case`. |
| 3 | **major** | `src/Simulations.jl:618`, also `src/Simulations.jl:601` | After a successful run, a forced recomputation threw. Pass 3 still loaded the earlier result, ran the newly configured post-processor and persisted its changes. The same summary recorded one failed solver and one successful post-processing run. Gate the later passes on each task’s pass-1 outcome so failed or empty recomputations leave earlier results intact. See `failed_rerun_case`. |
| 4 | **major** | `src/IOUtils.jl:181`, `src/IOUtils.jl:394` | With the conversion cache on, the first Lagrangian read carries `:derived => :conversion`. The cache hit strips that marker because the reader installs the native file’s metadata. After switching to an empty save root, `calculate_all_stats!` persisted that cached conversion as the native simulation. Restore the derived kind when reading conversion entries, including the all-entries loader. See `conversion_cache_case`. |
| 5 | **major** | `src/Simulations.jl:434` | For a constant solution of 1, changing `config.reference` from a factory returning 1 to one returning 2 kept the stored L1 error at 0. The summary counted the statistics as cached. A forced stats pass gave 2 on the same two-node grid under the package’s rectangle rule. Record the reference identity with evaluated statistics and invalidate the affected values on a change. `force_stats=true` with `calculate_stats=true` works around this. See `statistics_case`. |
| 6 | **major** | `src/ConversionUtils.jl:65` | Two Float16 particles of constant value 2 at positions 0 and 1 converted onto those same grid nodes as `[NaN, NaN]`. The weight floor rounds to zero in Float16, and an exact node hit contributes an infinite weight. Use a wider accumulator and handle coincident particles with finite normalized weights. See `half_precision_case`. |
| 7 | **major** | `src/StatCalculation.jl:164`, also lines 162 and 166 | For the two-component solution `(1, 2)` and reference `(0, 2)`, only the first relative mass is undefined. The second is 1, but the entire `:relative_mass` statistic disappeared. Drop a statistic only when every component at every sample is NaN. See `statistics_case`. |
| 8 | **major** | `src/Simulations.jl:636` | A zero-byte file with the correct cache filename caused the entire batch call to throw `EOFError`. Pass 1 caught the read failure, then the final `files` lookup reopened the same file outside the per-task error handler, losing the summary. Handle unreadable files during summary construction and report `nothing` for an unusable file. See `unreadable_case`. |
| 9 | **major** | `src/Examples/advection_1d.jl:26` | At speed −1, CFL 1, four periodic cells and one step, the upwind example produced 2 at `x=0.25`. The exact one-cell left shift gives 0 there. The step size already accounts for the speed magnitude, but the stencil always takes its difference from the left. Select the upstream neighbor by the sign of the speed, or reject negative speeds explicitly. See `upwind_case`. |
| 10 | **minor** | `src/DataManagement.jl:368` | Two runs containing `:solver=>"alpha"` and `:param_solver=>"beta"` respectively put both values into the same `param_solver` column of `sim_data_table()`. The prefix is chosen independently for each row, so a column changes meaning between runs. Allocate column names once from the union of the matched parameter keys. See `table_case`. |
| 11 | **minor** | `src/DataManagement.jl:26` | `check_data` on a two-node Eulerian BigFloat field `[1, 2]` threw `MethodError` in `_health_frame`. The component mean retains BigFloat, while the frame builder requires rows with exactly Float64 elements. Accept real-valued rows and convert at the output boundary or preserve their precision throughout. See `bigfloat_case`. |
| 12 | **minor** | `src/StatCalculation.jl:88` | `add_stat!(d, :spatial, 1.0, :space)` on a two-node, two-component grid registered an x-dependent statistic but stored only one component vector. The scalar path skips the retained-axis shape check. Require one value per retained coordinate, or broadcast the input into the documented spatial shape. See `statistics_case`. |
| 13 | **minor** | `presets/hyperbolic.jl:89` | The second component of a solution exactly matched its reference, but the absolute mass error was `1.0e-9`. Every smaller real discrepancy also gets this published value. Return the measured absolute error and apply a floor only in a plot that requires a logarithmic scale. See `statistics_case`. |
