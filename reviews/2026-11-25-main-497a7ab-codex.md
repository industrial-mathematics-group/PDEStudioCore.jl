## Findings introduced by #65

1. **Major. A legacy user metadata field can trigger an automatic recomputation and be overwritten on upgrade.** At `src/Simulations.jl:356–357`, any stored string called `:configuration_source` is taken for an earlier pipeline digest. I used the first parent to run a solver that attached the user string `"calibration record 47"` to that key. Re-running on the first parent with unchanged source bytes reported a hit and preserved the value. On #65, `on_changed_sources = :recompute` reported one changed run and replaced the string with a SHA-256 digest. Distinguish new pipeline provenance from legacy user metadata, for example through a dedicated versioned entry. [Change detection](../src/Simulations.jl#L348) · [Upgrade output](2026-11-25-main-497a7ab-codex-evidence/source-metadata.txt)

## Other findings in the whole-codebase snapshot

1. **Critical. Nested `nothing` and `missing` can alias their type objects.** The top-level cases are handled explicitly at `src/Serialization.jl:455–457`, while container elements go through `val2str`. Both `Any[nothing]` and `Any[Nothing]` normalize to `Any[Nothing]`. With a solver that distinguishes them, the second run reused 10 where a fresh run returned 20. `Any[missing]` and `Any[Missing]` likewise share a hash. The first parent reproduces both identities. Preserve the singleton value inside containers, or refuse a container whose identity would change on normalization. Apply the frozen hash format's migration rules. [Rendering](../src/Serialization.jl#L62) · [Normalization](../src/Serialization.jl#L451) · [Two-revision evidence](2026-11-25-main-497a7ab-codex-evidence/README.md)
2. **Critical. Distinct NaN payloads in accepted `Val` tags can alias runs.** `src/Serialization.jl:528` and `:564–575` allow Float64 type parameters. Two `Val` tags with distinct NaN payloads are different Julia types, yet both normalize to `Val{NaN}()`. A solver that branches on the tag returned 10 for the first and would return 20 for the second. The second configuration got the first result from cache. The first parent has the same collision. Refuse type-parameter values that cannot be represented faithfully, or encode their identity without depending on printed text. [Type validation](../src/Serialization.jl#L552) · [Two-revision evidence](2026-11-25-main-497a7ab-codex-evidence/README.md)
3. **Major. Changing the active statistic registry can erase the record of a statistic that remains stored.** At `src/StatCalculation.jl:302`, `evaluated_stats` is replaced by the current names. I computed L1 against A, unregistered L1, and computed L2 against the same A. The file retained L1 = 2 but its evaluation list became `[:l2error]`. Switching to B refreshed L2 while leaving L1, and re-registering L1 returned `:cached` with 2. The correct result against B is 6. Both revisions reproduce this. Retain provenance for inactive evaluated statistics until they are removed, or store reference provenance per statistic. [Record writer](../src/StatCalculation.jl#L294) · [Current output](2026-11-25-main-497a7ab-codex-evidence/statistics.txt)
4. **Major. The earlier source-role cache issue persists for runs written before #65.** I prepared a run with `b.jl` last on the first parent, then changed to the configuration with `a.jl` last on #65. Both configurations use one helper and one final override. With `on_changed_sources = :recompute`, the old run returned 20, although the new configuration computes 10. `src/Simulations.jl:356–357` deliberately compares the final file only when the old record has its digest. A fresh-store control correctly detects the change. Document the upgrade limitation in the source guide or treat missing legacy provenance as unknown when recomputation is explicitly requested. [Digest comparison](../src/Simulations.jl#L348) · [Fresh control](2026-11-25-main-497a7ab-codex-evidence/source-fresh.txt) · [Upgrade output](2026-11-25-main-497a7ab-codex-evidence/source-legacy.txt)
5. **Minor. Hardlinks still pass duplicate-source detection.** At `src/Simulations.jl:371–374`, resolving symbolic links does not unify different hardlink paths. Julia's `samefile` confirmed both inputs designated the same file. Both versions included it twice and returned a counter value of 2. #65 rejects the symlink control before any include. Compare file identity for existing paths, or describe the check as requiring distinct canonical paths. [Source check](../src/Simulations.jl#L371) · [Output](2026-11-25-main-497a7ab-codex-evidence/hardlink.txt)
6. **Minor. Extreme finite Float64 values can produce infinite diagnostics.** At `src/DataManagement.jl:15`, summing three values equal to `floatmax(Float64)/2` overflows before the mean is taken. At `presets/hyperbolic.jl:30`, the L2 preset squares the field before scaling it by the integration measure. On two nodes spaced by `1e-200` with values `1e200`, it returns infinity, while the higher-precision control gives about `1.414213562373095e100`. Both cases reproduce on the first parent. Use scaled accumulation for the mean and weighted norm. [Health check](../src/DataManagement.jl#L5) · [L2 preset](../presets/hyperbolic.jl#L29) · [Control](2026-11-25-main-497a7ab-codex-evidence/numerics.txt)
