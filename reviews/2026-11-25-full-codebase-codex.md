## Findings in the whole-codebase snapshot

1. **Critical. Scalar integer normalization can return a cached result for a different parameter.** At `src/Serialization.jl:58–59` and `:455–457`, scalar numbers are written as display text and read back as literals. On 64-bit Julia `UInt64(1)`, `Int128(1)`, and `BigInt(1)` all become `Int64(1)`. The data guide specifies that numbers keep their type except for the stated narrow-float normalization. With a solver that returns 10 for signed inputs and 20 for unsigned inputs, the second of two configurations reported a hit and returned 10 for `UInt64(1)`. Forcing that unsigned run gave 20. Preserve the scalar type in the identity or reject unsupported scalar representations before lookup. Changing an accepted value's identity needs the versioned hash and import treatment specified in the repository. [Number rendering](../src/Serialization.jl#L58) · [Two-revision output](2026-11-25-full-codebase-codex-evidence/README.md)
2. **Critical, previously reported. Custom integer values bypass their declared identity.** `src/Serialization.jl:521` and `:546` admit a user-defined `Integer` through the plain-value path. Two values with different declared `variant` fields print as `2`. They produced the same stored value and the second read 10 from cache where its solver would return 20. The #60 dictionary-key restriction is working. Restrict the built-in numeric path to documented scalar types and honor custom declarations before formatting those values. [Parameter validation](../src/Serialization.jl#L521) · [Current rerun](2026-11-25-full-codebase-codex-evidence/custom-values.txt)
3. **Major. A metadata-only save can make stale statistics appear current.** At `src/IOUtils.jl:426`, an explicit save passes no evaluation records. The rewrite at `:370` drops `evaluated_stats` and carries the remaining reference entries. Later, `src/Simulations.jl:399` relies on that list to identify values to remove during a reference change. I calculated L1 = 2 against A and saved a note to `data.metadata`. After switching to B with only L2 registered, re-registering L1 reported `:cached` and still returned 2. The control without the metadata edit returned the correct 6, as did a forced refresh. Carry the evaluation records together when the solution and its computed statistics are preserved. Invalidate the affected values and records together when they change. [Save path](../src/IOUtils.jl#L416) · [Refresh](../src/Simulations.jl#L391) · [Control and reproduction](2026-11-25-full-codebase-codex-evidence/stat-rewrite.txt)
4. **Major. One sweep can silently discard a distinct float task.** At `src/Simulations.jl:248`, ordinary `isequal` treats exactly representable `1.5f0` and `1.5` as equal. Both normalize to the same value by design. A sweep over `Any[1.5f0, 1.5]` ran only the first task, returning 10. Isolated runs show that the solver can distinguish the inputs and return 20 for Float64. Extend collision detection to compare original parameter types and values recursively, including cases where Julia's equality promotes across types. The existing `0.1f0` and `0.1` test covers raw values that Julia already considers unequal. [Task generation](../src/Simulations.jl#L244) · [Current output](2026-11-25-full-codebase-codex-evidence/pipeline.txt)
5. **Major. Reordering source includes can silently reuse obsolete results.** `src/Simulations.jl:351` compares digests as a set, although `:365` includes files in order. Two source files assigned the same global coefficient. With `[a, b]` the field was 20. Reversing them with `on_changed_sources = :recompute` reported zero changed tasks and returned cached 20. Forcing the same configuration computed 10. Store and compare the digest sequence in actual inclusion order, keeping the path-to-digest map for provenance. [Change detection](../src/Simulations.jl#L343) · [Current output](2026-11-25-full-codebase-codex-evidence/pipeline.txt)
6. **Major. Adding a reference can leave finite fallback statistics cached.** `src/Simulations.jl:521–525` checks reference availability only for previously evaluated names absent from the file. A custom statistic that returns the numerical value when the reference is unavailable and the analytical value otherwise stored 1 in the initial run. Configuring the new reference returned `:cached` and 1 even though the reference is 3. A forced statistics pass returned 3. Treat the transition from a recorded evaluation without a reference as making those statistics due, including finite ones. [Cache decision](../src/Simulations.jl#L512) · [Current output](2026-11-25-full-codebase-codex-evidence/pipeline.txt)
7. **Major. Equal mixed-type sets can get different run hashes.** `src/Serialization.jl:75` orders dictionary keys by display text, and the generic serializer at `:80–84` uses the internal dictionary to render a set. The dictionary key check does not guard that branch because the set is checked by its elements. I inserted the same 50 string/symbol pairs into two `Set{Any}` values in opposite orders. Julia considers the sets equal, but stored text order differed where a string and symbol have the same display text. The second configuration ran again and created a second file. Reject sets whose identities cannot be represented canonically, or give sets an explicit versioned encoding sorted by their encoded elements. [Container rendering](../src/Serialization.jl#L70) · [Two-revision output](2026-11-25-full-codebase-codex-evidence/README.md)
8. **Minor, previously reported. Two descriptions in the data guide need qualification.** At `docs/src/data.md:168`, the statement that import skips foreign files also covers alternate filenames, although a valid external source named `renamed-run.jld2` imported successfully. At `:180` and `src/Serialization.jl:554–556`, the integer key wording should name the fixed-width types. The allowlist intentionally excludes `Bool` and `BigInt`. [Data guide](../docs/src/data.md#L166) · [Current reruns](2026-11-25-full-codebase-codex-evidence/README.md)
