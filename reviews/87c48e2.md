## Findings

### 1. High — CONFIRMED — `_type_size` counts parameters, not layout: nested StaticArrays still abort Julia (old Finding 1 is not closed)
- **Where:** `src/Serialization.jl:123-143` (`_type_size`, `_checked_type`), `:251-253` (dictionary check), `:178-179` (`getindex`).
- **What goes wrong:** `SVector{N, T}` = `SArray{Tuple{N}, T, 1, N}`. `N` is a value parameter and counts as 1, but the layout holds `NTuple{N, T}`. So `SVector{64, SVector{64, SVector{64, Int}}}` has a `_type_size` of about 15, but it is an isbits struct of 262,144 Ints: the type of old Finding 1.
- **Scenario:**
  - `Dict{SVector{64, SVector{64, SVector{64, Int}}}, Int}()` (55 chars): abort (exit 134).
  - Exit 139 (segfault): the 256 form, `IdDict{…}()`, `Pair{…}[]`.
  - `Dict{SVector{256, SVector{256, Int}}, Int}()` (44 chars): > 120 s. `Dict{Int, SVector{256, SVector{256, Int}}}()`: 9.4 s.
  - `SVector{1000, SVector{1000, Int}}[]` (35 chars) parses (it was a String before), and hashing it throws `StackOverflowError`.
  - `Dict(SA[1, …×10^4] => 1)` (30 KB): 56.7 s.
- **Evidence:** `probes/probe_static.out`, `probes/probe_sa_values.out`. The previous parser aborts too (`probes/probe_old_static.out`).
- **Fix:** bound the layout of concrete types. Either recurse over `fieldtypes(T)` in `_type_size` with an early stop, or reject `isconcretetype(T)` with `(isbitstype(T) ? sizeof(T) : Base.datatype_fieldcount(T)) > 2^13`. Apply it in `_checked_type` and to `typeof(p.first)`/`typeof(p.second)`.
- **Test:**
  - `@test str2val("Dict{SVector{256, SVector{256, Int}}, Int}()") isa String`
  - `@test str2val("SVector{1000, SVector{1000, Int}}[]") isa String`
  - the `SA` key → String
  - Add the three-level forms only after the fix.

### 2. High — CONFIRMED (pre-existing) — StaticArrays with a large `Size` and a free length make `T[x]` run out of memory in type inference
- **Where:** `src/Serialization.jl:177-179`. `_checked_type` doesn't bound `prod(Size)`, and it skips `UnionAll`s. The cap of 1024 applies to each `Tuple{…}` entry separately.
- **Scenario:**
  - `SArray{Tuple{1000, 1000, 1000}}[[1.0]]` (38 chars): "Internal error: during type inference of getindex(…) … OutOfMemoryError()", then the process exits.
  - `SArray{Tuple{256, 256, 256}}[[1.0]]` does the same with the old parser.
  - `SArray{Tuple{100, 100, 10}}[[1.0]]`: 4.9 s / 2.3 GiB.
- **Evidence:** `probes/probe_static.out`, `probes/probe_types.out`, `probes/probe_old_static.out`.
- **Fix:** for `T <: StaticArray`, including `UnionAll`s, reject `prod(Size) > 1024` in `_checked_type`.
- **Test:** `@test str2val("SMatrix{1000, 1000}[[1.0]]") isa String`.

### 3. High — CONFIRMED (pre-existing) — Big-number ranges are bounded per element and in length, but not in total
- **Where:** `src/Serialization.jl:245`, `:103-115`.
- **Scenario:**
  - `BigInt(2)^524288:BigInt(2)^524288+999999` (40 chars) parses in 4.8 s. `calculate_hash`/`_normalize_param` then aborts with LLVM out of memory: 10^6 elements of 157,827 digits each, about 158 GB of text.
  - 1000 elements: hashing takes 10.5 s.
  - Rational{BigInt} ranges behave the same.
- **Evidence:** `probes/probe_bigrange.out`, `probes/probe_bigrange_detail.out`, `probes/probe_old_misc.out`.
- **Fix:** accept ranges only of fixed-size element types, or bound `length × bits`.
- **Test:** the 1000-element form → String.

### 4. Medium — CONFIRMED (pre-existing) — Nesting depth is unbounded
- **Where:** `src/Serialization.jl:164-194`. Every level is a new type to compile.
- **Scenario:** 201-char vector: 2.9 + 2.2 s. 551-char Dict: 5.0 + 1.8 s. 2001 chars: > 120 s. 3001-char tuple: 24.7 + 21.3 s. At depth 10^5 the parser overflows the stack ("program state may be corrupted").
- **Evidence:** `probes/probe_nest.out`.
- **Fix:** a depth limit of 16–32 levels (the deepest stored form is `NTuple{4, NTuple{4, Float64}}`). Optionally a text-length cap before `Meta.parse`.
- **Test:** `["^100 … "]"^100` → String, fast.

### 5. Medium — CONFIRMED (regression) — `_is_fixed_size` recurses forever on Rationals
- **Where:** `src/Serialization.jl:118-119`. For a `Rational`, `real(x) === x`.
- **Scenario:**
  - `sqrt(1//4)`, `exp(1//2)`, `sin(1//2)`, `log(3//2)` and `sqrt(…//… + 0im)` overflow the stack. They come back as Strings (they were Float64/ComplexF64), so the hash text changes, and each call prints "program state may be corrupted".
  - Only hand-typed calls are affected.
- **Evidence:** `probes/probe_parity.out`, plus direct runs.
- **Fix:** `_is_fixed_size(x::Rational) = _is_fixed_size(numerator(x))` and `_is_fixed_size(x::Complex) = _is_fixed_size(real(x)) && _is_fixed_size(imag(x))`.
- **Test:** `@test str2val("sqrt(1//4)") === 0.5`, `exp(1//2)`, the Complex form, and `sqrt(big"1"//3)` → String. Add these to the corpus.

### 6. Low — CONFIRMED (pre-existing) — `IdDict` is allowlisted, but `val2str` can't write it
- **Scenario:** `str2val("IdDict(1 => 2)")` returns an `IdDict`, and `calculate_hash` then throws `UndefRefError`.
- **Fix:** remove `IdDict` (and `AbstractDict`) from the allowlist.
- **Test:** `IdDict(1 => 2)` → String.

### 7. Low — CONFIRMED — The differential test's part 4 misses `using`-reachable types (about 130)
- **Where:** `names(mod; imported = true)` excludes names brought in by `using`.
- **Effect:**
  - `SA_F64[…]`/`SA_F32[…]` are Strings now, and the hash text changes.
  - `SubString{String}[…]` (from `split`), `BitVector`, `Size` and `Colon` are Strings now, with the same hash text.
  - No stored data is affected.
- **Fix:** allowlist `SA_F64`/`SA_F32`. Fix the comment, or use `usings = true`, and list the newly refused names.
- **Test:** add these forms to the corpus.

## Addressed findings of reviews/8fe6120.md

1. **Nested type parameters:** NOT OK. Fixed for `NTuple`, not for StaticArrays (Findings 1, 2).
2. **Long tuple Dict keys:** OK for tuples (58.9 s at the old code → String). NOT OK for `SA` keys (56.7 s).
3. **BigFloat with huge exponents:** OK. Every case of the old finding is a String, and no other BigFloat path costs more than 0.3 s. The fix introduced Finding 5.
4. **Parameters above 256:** OK.
5. **Rational step ranges:** OK. Huge ones are cheap Strings.
6. **High-N `Array` types:** OK (`UnionAll`s are unchecked but cheap).
- **Minor issues:**
  - The `typemin(Int)` check is unchanged (harmless now).
  - The docs are updated, but they overclaim.

## Test coverage

- The new tests pass. 15 of the 24 bound tests distinguish the old code. The round-trip table is a regression guard.
- The differential test's allowed differences and hash exemptions are justified. It misses Findings 5–7.
- The real-data check (4340 datasets, 149,850 values, 0 differences) strongly supports the hash claim. A synthetic corpus with its 82 (key, type) kinds would be cheap to add.

## Minor issues

- `docs/src/data.md:116` and the code comment at `:57-62` claim nothing can make Julia stall. Findings 1–4 contradict this.
- The docstring's allowlist list omits `IdDict`, `Type`, `UnionAll`, `Function`, `Irrational`, `Complex`, `Rational` and the abstract number types. Its rule "sin/sqrt of a BigInt or BigFloat" now effectively also covers Rationals.
- The `^` pre-check is conservative: `BigInt(2)^524289` is refused although the result has about 2^19 bits.
- `_checked_type` checks `N` only for `DataType`s (`SArray{Tuple{2}, Int, 1000}` is accepted, but cheap).
- Odd but inert types are accepted: `SVector{-1, Int}`, `Irrational{1}`, `Dict{Union{}, Int}()`.
- The Union branch of `_type_size` can return about `2 * (limit + 1)`, contrary to its comment.

## Verdict

The allowlist is a clear improvement:
- Names outside numbers, text, containers and StaticArrays can no longer be reached.
- The BigFloat crash class is closed.
- Large single parameters, Rational ranges and high-N Array types behave as intended.
- The hash claim holds on real data.
- 874/874 tests pass.

But "everything built is bounded" does not hold: StaticArrays hide their size (55- and 38-character crashes), big-number ranges blow up when hashed, nesting depth is unbounded, and the new `_is_fixed_size` overflows the stack for Rationals.

Findings: 3 high (1, 2, 3), 2 medium (4, 5), 2 low (6, 7). Findings 2, 3, 4 and 6 are pre-existing; Finding 5 is a regression of this commit.
Addressed items:
- 1: NOT OK.
- 2: OK for tuples, NOT OK for `SA`.
- 3, 4, 5, 6: OK.
