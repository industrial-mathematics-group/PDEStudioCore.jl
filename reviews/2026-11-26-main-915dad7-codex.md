## Findings in this change

1. **Major. Editing a legacy dataset can write format 4 with stale derived statistics and block every subsequent refresh.** The save at `src/IOUtils.jl:426–434` authorizes replacing the old file if the solution differs. A genuine 0.9 run had field `[1, 1]` and a stored `l2norm = √2`. I loaded it, set the field to `[2, 2]`, and called `save_sim_data(data; overwrite = true)`. #74 wrote format 4 with `l2norm = √2`, and the next statistics pass failed because it treated that value as solver-owned. The first parent dropped the stale value and the next pass wrote `√8`. Reserve format-changing replacement for an explicit solver recomputation. If saving elsewhere should also be refused for a dataset read from an older format, retain its source format independently of solution equality. [Save decision](../src/IOUtils.jl#L421) · [Write guard](../src/IOUtils.jl#L595) · [Current output](2026-11-26-main-915dad7-codex-evidence/format-edit-head.txt) · [First parent](2026-11-26-main-915dad7-codex-evidence/format-edit-base.txt)
2. **Minor. A normal integration measure can still produce a spurious zero L2 norm.** The fallback at `src/StatCalculation.jl:111` evaluates `maximum_magnitude * sqrt(measure)` before multiplying by the norm of the normalized samples. For four values of `1.4e-174` with normal spacing `2e-300`, that intermediate rounds to zero. The final norm rounded from BigFloat is `5e-324`, which the first parent returns. A zero field compared with that constant reference also loses its relative L2 error on #74, although the exact result is 1. Combine binary exponents for the final product or explicitly reject an intermediate outside the supported range before returning a numeric result. [L2 fallback](../src/StatCalculation.jl#L96) · [Current output](2026-11-26-main-915dad7-codex-evidence/l2-head.txt) · [First parent](2026-11-26-main-915dad7-codex-evidence/l2-base.txt)
3. **Minor. Loading a conversion with caching enabled writes to the format 3 file.** With `enable_cache!(true)`, `load_sim_data(params, :eulerian, (3,))` on the original 0.9 file rewrites its bytes and adds `conv_E_3` under the format 3 header. The resulting grid is usable. The write contradicts the newly documented boundary. Return the calculated conversion and only append it to the file when its format matches the writer. The Lagrangian path uses the same unguarded append. [Conversion cache writes](../src/IOUtils.jl#L688) · [Observed output](2026-11-26-main-915dad7-codex-evidence/format-boundary.txt)
4. **Minor. The statistics pass accepts and rewrites an unknown later file format.** The new guards use a lower bound in `src/Simulations.jl:415` and `src/IOUtils.jl:599`, although the contract requires the writer's own format. I took a fresh run and used a format 5 header to simulate a later layout. Import refused it, then the statistics pass rewrote it as format 4. The current release produces no format 5 data. Require equality in the statistics and post-processing paths and on in-place saves, with an error identifying a newer file. [Statistics guard](../src/Simulations.jl#L410) · [Writer guard](../src/IOUtils.jl#L595) · [Simulated later-file output](2026-11-26-main-915dad7-codex-evidence/format-future.txt)
5. **Minor. The public import help still promises support for formats the importer rejects.** At `src/DataManagement.jl:150–155`, the docstring says imports accept the file format of PDEStudioCore 0.5 and later. A 0.9 file returns zero imports under #74. State the current format requirement in the API help and link to the external-conversion or recompute instructions. [Import docstring](../src/DataManagement.jl#L145) · [Importer validation](../src/DataManagement.jl#L270) · [Observed output](2026-11-26-main-915dad7-codex-evidence/format-boundary.txt)

## Outside this change

- **Minor, residual #70 ownership issue.** A stored format 3 work-in-progress snapshot with incorrect ownership still loses its solver statistic in memory if passed to `calculate_all_stats!(data; save = false)`. The actual #70 writer assigned the post-processor both `:calibration` and `:quality`. The current loader exposes that old record, and evaluating the unrelated `:maintenance` statistic drops calibration from the object. The file stays byte-for-byte unchanged. The cascade that trusts the ownership dates to the earlier statistics layers. The ordinary on-disk refresh is now guarded. An origin-format check before using an old ownership record would also cover the direct API. [Cascade](../src/StatCalculation.jl#L301) · [Reproduction](2026-11-26-main-915dad7-codex-evidence/format-in-memory.txt)
