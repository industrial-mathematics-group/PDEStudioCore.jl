## Findings

### 1. High — CONFIRMED — `_type_size` counts `prod(Size)`, not the length parameter `L`: nested static arrays still abort Julia (78 chars)
- **Where:** `src/Serialization.jl:141-152`, the static array branch of `_type_size`. It is used by `_checked_type` and by the `Dict` key/value check at `:310-313`.
- **What goes wrong:** `SArray{S, T, N, L}` stores `data::NTuple{L, T}`. The new branch counts elements from `S` only, and `L` counts as one parameter. A type with `S = Tuple{0}` or `Tuple{}` and `L = 64` therefore has `_type_size` 6, but it holds 64 elements. Nested three levels deep, that is 262,144 Ints: the layout of old Finding 1, with the size check bypassed.
  - The curly check allows `L` ≤ 1024 per level.
  - No value of such a type can exist (the inner constructor checks `L`), but building the `Dict`/`Pair` type compiles for its layout.
- **Evidence** (`probes/probe_static_length.out`, `probes/probe_type_size.out`):

  | Literal | Result |
  |:--|:--|
  | `Dict{SArray{Tuple{},SArray{Tuple{},SArray{Tuple{},Int,0,64},0,64},0,64},Int}()` (78 chars) | `LLVM ERROR: out of memory`, exit 134 |
  | the same with `Tuple{0}` (89 chars) | `std::bad_alloc`, exit 134 |
  | `Pair{…}[]` | exit 134 |
  | `Dict{SArray{Tuple{1}, …, 1, 64}…}()` | exit 134 |
  | `Dict{SArray{Tuple{0}, SArray{Tuple{0}, Int, 1, 256}, 1, 256}, Int}()` | > 120 s |

  `MArray` with the same shape is cheap (heap-allocated).
- **Fix:** for `SArray`/`MArray`, treat a concrete `L` that differs from `prod(S)` as no literal (such types can't hold values). Otherwise count `max(prod(S), L)` elements. Simpler alternative: count the layout generically through `fieldtypes` (`NTuple{L, T}` is then counted by the existing parameter recursion).
- **Test:**
  - `@test str2val("Dict{SArray{Tuple{0}, SArray{Tuple{0}, Int, 1, 256}, 1, 256}, Int}()") isa String` (it hangs at 76c67a1, so run the new test only after the fix)
  - `@test str2val("SArray{Tuple{}, Int, 0, 1000}") isa String` (or check its size)
  - keep `SMatrix{2, 2, Float64, 4}` parsing

### 2. Medium — CONFIRMED — `_too_nested` reads the Char literal `'"'` (and `#` comments) as the start of a string
- **Where:** `src/Serialization.jl:263-284`. The scanner toggles `quoted` on every `"` outside a string, including the one inside `'"'`, which `val2str` writes for that Char, and one inside a comment.
- **Effect A (missed nesting):** everything after `'"'`, up to the next `"`, goes unscanned. `('"', ` + `"["^2000 * "1" * "]"^2000` + `)` (4 KB) reaches `Meta.parse` and overflows its stack in the main thread and in tasks ("Warning: detected a stack overflow; program state may be corrupted"). It returns a String.
  - The same happens after `1 # "\n` (comments).
  - This is the crash class the commit says it closes ("brackets … in the text before Meta.parse, which overflows its stack"). The process keeps working afterwards (`probe_after_overflow.out`).
- **Effect B (wrong rejections, regression of 76c67a1):** after `'"'`, the scanner treats the contents of the next real string as code. Values `val2str` writes no longer round-trip:
  - `Any['"', "("^40]` → String (was `Vector{Any}`)
  - `('"', "-"^1100)` → String (was `Tuple{Char, String}`)
  - `('"', "x", "["^33)` → String
  - The hash text is unchanged (the String fallback is the same text), but the normalised value changes type. Only contrived values are affected; the real data has none.
- **Evidence:** `probes/probe_nest_bypass.out`, `probes/probe_overflow_depth.out` (threshold between 1500 and 2000 brackets), `probes/probe_parity_nest.out`.
- **Fix:** lex Char literals: on `'`, skip one character or one escape sequence and the closing `'` (adjoint `'` only follows an identifier, a number or a closing bracket). Reject `#` outside strings. A more robust option is item 3's tokenizer approach.
- **Test:**
  - `@test str2val("('\"', " * "["^2000 * "1" * "]"^2000 * ")") isa String`, together with a direct `@test PDEStudioCore._too_nested(…)`, because a parser overflow also yields a String
  - `@test str2val(val2str(Any['"', "("^40])) == Any['"', "("^40]`

### 3. Low — CONFIRMED (pre-existing, partly addressed) — Nesting without brackets, and operator chains split by newlines, still overflow `Meta.parse`
- **Where:** `_too_nested`. Only `([{` count as depth, and only `_OPERATOR_CHARS` count as operators. The count resets at `\n`, but Julia continues an expression after a trailing binary operator.
- **What still overflows** (stack overflow, then String):

  | Text | Shortest overflow |
  |:--|:--|
  | `1''''…` (adjoint) | 8 KB |
  | `$$$…1` | 10 KB |
  | `begin …` × 3000 | 30 KB |
  | `a.a.a…` | 20 KB |
  | `"1-\n"^10^4`, `"2^\n"^10^4` (scanner returns false) | 30 KB |
  | Unicode operators outside the set: `±±…1`, `1 → 1 → …`, `1 × 1 × …` | 10^5 repetitions |

  All return a String within 0.7–9 s. No crash; the process continues.
- **Evidence:** `probes/probe_nest_bypass.out`, `probes/probe_overflow_depth.out`, `probes/probe_newline_chain2.out`.
- **Fix:** count on tokens, not characters. The Julia tokenizer (`Base.JuliaSyntax.tokenize`) is iterative. Then:
  - reject keywords, `$`, comments and adjoint `'`
  - count every operator token, any Unicode operator included
  - count bracket depth
  - reset the operator count only at `,`/`;`, not at newlines

  Or, at minimum: don't reset at `\n`, and count `'`, `$`, `.` before a letter, and any non-ASCII operator character.
- **Test:**
  - `@test PDEStudioCore._too_nested("1-\n"^2000 * "1")`
  - `@test PDEStudioCore._too_nested("1" * "'"^10^4)`
  - `@test PDEStudioCore._too_nested("begin "^3000 * "1" * " end"^3000)`

## Verdict

The commit closes most of what reviews/87c48e2.md found:
- the `Size`-based static array crashes and the free-size inference blow-up
- the big-number ranges, which now hash in under 0.3 s at the limit
- the expression-depth stalls (≤ 2.4 s at depth 32)
- the Rational stack overflow
- the `IdDict` and `using`-name gaps

Hash stability holds: over 4340 datasets and 149,850 values there are 0 parse and 0 hash-text differences, and every difference found in the synthetic values keeps the hash text. `str2val` still calls no `eval`. The suite passes 1107 / 1107, and the new tests separate the old code from the new.

The bound on static arrays still misses the length parameter: a 78-character `Dict{SArray{Tuple{}, …, 0, 64}…}()` aborts Julia (Finding 1). The text scanner meant to keep `Meta.parse` from overflowing misreads `'"'` and comments (Finding 2). It also doesn't see nesting without brackets or chains split by newlines (Finding 3). Stack overflows therefore remain reachable from 4 KB texts, and a few contrived values `val2str` writes no longer round-trip.

Findings: 1 high (1), 1 medium (2), 1 low (3). Finding 1 reopens old Finding 1 by another route; part B of Finding 2 is a regression of this commit; Finding 3 is pre-existing.
