## Findings

### 1. Medium — CONFIRMED — A separator inside a closed group drops its chain from the outward carry (8 KB overflow)

- **Where:** `_too_nested`, `src/Serialization.jl:289-296`. `K","`/`K";"` set `terms = 0`, and a closing bracket carries `enclosing + max(terms, 1)`, i.e. only the tokens since the group's last separator.
- **What goes wrong:**
  - The commit message says chains spread over levels "before or after the inner group" are bounded. That holds only if the inner group's chain is its last element.
  - Put the chain first and close the group with `, 1)`. The group then carries 1 token, and the next level starts a new chain of up to 1023 tokens around it.
  - With left-associative or postfix chains, each level adds about 511–1022 Expr levels. Each open bracket sits at the start of an element, so the path budget `open` stays 0.
  - The pattern is `lv(L, chain) = foldl((inner, _) -> "(" * inner * chain * ", 1)", 1:L; init = "1")`.
- **Evidence:** `probes/check_all.out`, `run_all.out`, `run_lit2.out`, `run_task.out`. `_too_nested` is false for every text below; each logs StackOverflowError plus "program state may be corrupted" and returns a String after 0.7–0.8 s.

  | Text | Size | Result |
  |:--|:--|:--|
  | `lv(8, "'"^1022)` | 8 KB | overflow (main thread and `Threads.@spawn`); 6 levels: none |
  | `lv(8, "[1]"^1022)`, `lv(16, "(1)"^1022)` | 24–49 KB | overflow |
  | `lv(16, "-1"^511)`, `"::T"^511`, `" where T"^511`, `"|>f"^511` | 16–65 KB | overflow |
  | same with `; ` (block), `[ , ]`, `[ ; ]`, `{ , }`, trailing `,`, `f( ; )`, `T{ , }`, `Dict( , )` (16 levels) | 16 KB | overflow |

- **Fix:** carry the longest chain of the group, not its last one. Keep `longest` per level: push and pop it with `terms`, and at a separator do `longest = max(longest, terms)`. On a closer, `terms = enclosing + max(longest, terms, 1)`. The diff against the current code:
  ```julia
  push!(outer, (terms, longest)); ...; terms = longest = 0                   # opener
  inner = max(longest, terms, 1); (enclosing, longest) = pop!(outer)         # closer
  open -= enclosing; terms = enclosing + inner
  longest = max(longest, terms); terms = 0                                   # `,` / `;`
  ```
  `probes/patched.jl` implements this. It rejects every `sep_*` text and changes no decision on the 203 `val2str` parity values (`probe_parity_*_fix.jl`, "fix-no-exempt"). `val2str` elements are a few tokens each, so the longest element stays small.
- **Test:** `lv` as above; `@test T(lv(8, "'"^1022)) && T(lv(16, "-1"^511)) && T(lv(16, "-1"^511; sep = "; "))`. Also add a guard where the inner group comes first: `!T(val2str(nestlast(30, 100)))` with `nestlast(n, k) = foldl((inner, _) -> Any[inner, collect(1:k)...], 1:n; init = Any[1])`. The new `nested` test always puts the inner group last.

### 2. Low — CONFIRMED — Refusing assignment tokens turns operator Symbols that `val2str` writes into Strings

- **Where:** `src/Serialization.jl:300-301` (`_JS.is_prec_assignment(k)`, unlike the keyword test, has no `previous != K":"` exemption). The comment at `:272-273` and the commit message say `val2str` writes these "only in texts that are no literals (structs, NamedTuples)".
- **What goes wrong:**
  - `val2str` writes such tokens in quoted Symbols: `:~`, `:(=)`, `:+=` (all `op=`), `:(:=)`, `:≔`, `:⩴`, `:≕`, `:.~`, `:.=`. The reference reads them as Symbols; 356e683 returns Strings.
  - The same holds for any value that contains one: `Symbol[...]`, `(:~, 1)`, `Dict(:~ => 1)`, `Val{:~}()`, the type `Val{:~}`, `Tuple{Val{:~}, Int}`.
  - The hash text stays the same, because the whole text becomes a top-level String that `val2str` writes verbatim. But the normalised value changes type:
    - `save_sim_data` stores `":~"` instead of `:~`.
    - `_files_with_params` compares stored values with `isequal(file_params[k], _normalize_param(v))`. So `find_sim_data` and `delete_sim_data` no longer match files written before this commit with such a value.
  - None of the 4340 cached datasets holds such a value.
- **Evidence:**
  - `probe_parity_new.out` rows 1–24 and 38–48, 63: 35 parse differences vs. the reference, 0 hash-text differences. At a1f8627 all 35 parsed like the reference (`probe_parity_new_a1f8627.out`).
  - `probe_filter.out`: a dataset with `:op => :~` saved at a1f8627, looked up at 356e683: `does_sim_data_exist` true, `find_sim_data(Dict(:op => :~))` finds 0 files.
- **Fix:** don't refuse an assignment token right after `:`, or right after a `(` that follows `:` (the `:(=)` form), the same way keywords after `:` are let through.
  - Checked with `probes/probe_patched.jl`: `x :~ 1, …` has depth 3. `a ? b :~ c, …`, `:+= 1, …` and `x:+=1, …` are parse errors. `:~ = 1, …` and `:(=) = 1, …` are still refused at the `=`.
  - With the exemption, the 29 Symbol, Val and Tuple rejections that hold no dotted operator go away.
  - Dotted forms (`:.~`, `:.=`) lex as `.` plus the operator in 1.13 and stay refused unless `.` before the operator is exempted too.
  - Otherwise, document the limitation and fix the comment.
- **Test:** `@test str2val(val2str(:~)) === :~ && str2val(val2str(Val(:~))) === Val(:~) && str2val("(:+=, 1)") == (:+=, 1)` together with the existing `T("x ~ 1, "^2000 * "1")`.
