## Findings in #68

1. **Major. Deleting an upstream statistic can leave a stale post-processing result.** `src/IOUtils.jl:423–426` preserves records when the solution and parameters match, and `src/Simulations.jl:489` subsequently checks only whether the post-processor's own output keys are present. A solver attached `weights = [2, 3]` and a post-processor stored their sum, 5. I deleted `weights` with `delete_stat!(data, :weights)`, followed by `save_sim_data(...; overwrite = true)`. The next run returned `:skipped` and retained 5. On the 0.9 comparison, the callback ran and returned its fallback value of −1. Compare the upstream keys on save and clear dependent post-processing outputs and records when those inputs change. This is separate from manually replacing a value under the same key, which stayed stale in both versions. [Save logic](../src/IOUtils.jl#L418) · [Post-processing check](../src/Simulations.jl#L478) · [Comparison](2026-11-25-v010-codex-evidence/README.md)
2. **Major. The post-processing guard permits schema changes to an upstream statistic.** At `src/Simulations.jl:513`, the check compares value digests. `src/StatLayers.jl:114–132` includes the total element count and bytes without encoding shape or kept axes. A callback changed a simulation statistic from keeping `:x` to keeping `:y` on a square grid. A second callback reshaped the resulting two-element vector to a `2×1` array. Both reported `:ran` and persisted the changes. Preserve or validate upstream sizes and resolved axis assignments along with contents. [Guard](../src/Simulations.jl#L495) · [Digest](../src/StatLayers.jl#L114) · [Output](2026-11-25-v010-codex-evidence/layers.txt)
3. **Major. Legacy layer migration depends on which methods happen to be loaded and can discard a valid statistic.** `src/StatLayers.jl:146–150` assigns every previously evaluated name without a currently loaded four-argument method to the reference layer. I wrote a genuine 0.9 store with the hyperbolic preset. On 0.10, before loading the preset, `stat_layer(data, :mass)` returned `:reference`. After loading the preset it returned `:simulation`. Refreshing L1 against a new reference with only the L1 implementation loaded removed the old mass from the file. With the preset installed the same refresh kept it. Avoid deleting legacy values from an inferred layer while their provenance is uncertain. Consider classifying known built-in names independently of runtime method loading. [Migration](../src/StatLayers.jl#L140) · [Two-store control](2026-11-25-v010-codex-evidence/legacy-layers.txt)
4. **Major. The public statistics function no longer returns the dataset.** `src/StatCalculation.jl:233–248` forwards the internal status symbol. The public docstring still says it returns `sim_data`. For an ordinary Eulerian dataset, `calculate_all_stats!(data; save = false)` returned the same dataset in 0.9 and a `Symbol` in 0.10. A caller chaining `.stats` fails. Keep the status return in the internal method and return the dataset from the public wrapper, or document the breaking return-type change. [Public entry point](../src/StatCalculation.jl#L211) · [Comparison](2026-11-25-v010-codex-evidence/README.md)
5. **Minor. A registered name with no implementation goes undiagnosed without a reference.** `src/StatLayers.jl:240–241` treats all names without a data-only method as reference statistics. Registering a typo with neither method and running without a reference reported `:cached` with no failure. The earlier version reported `:failed`, and the current `calc_stat` docstring still promises an error. Validate that each name has an implementation before deciding which layer is due. [Planner](../src/StatLayers.jl#L236) · [Comparison](2026-11-25-v010-codex-evidence/README.md)
6. **Minor. An unused reference factory can fail simulation-only statistics.** `src/Simulations.jl:424` constructs the reference callback whenever any statistics work is due and a reference is configured. I registered only a four-argument statistic. A throwing reference factory caused the statistics pass to fail before computing it. Removing the reference from the same config produced the expected 4. Initialize the factory only when the plan will evaluate a reference statistic. [Pipeline](../src/Simulations.jl#L408) · [Output](2026-11-25-v010-codex-evidence/layers.txt)

## Finding in #67

**Minor. The source-role upgrade documentation gives too narrow a version cutoff.** The guide says runs stored before 0.9 lack the configuration-file record. The tagged v0.9.0 writer also omitted it. Switching the final configuration file on that store with `on_changed_sources = :recompute` returned cached 20. A forced rerun returned 10. Explain the limitation in terms of whether the stored record exists. [Source guide](../docs/src/advanced_config.md#L89) · [v0.9.0 store output](2026-11-25-v010-codex-evidence/prior-source-role.txt)

## Outside these changes

- **Minor. The L2 preset can still overflow within the stated field-value range.** At `presets/hyperbolic.jl:30`, a two-node field of `1e149` with spacing `1e100` gives `Inf`. The finite weighted norm is about `1.414213562373095e199`. The pre-existing operation squares and multiplies by the measure before taking the root. Use scaled accumulation or document a limit that includes the integration measure. [L2 preset](../presets/hyperbolic.jl#L29) · [Independent calculation](2026-11-25-v010-codex-evidence/rechecks.txt)
