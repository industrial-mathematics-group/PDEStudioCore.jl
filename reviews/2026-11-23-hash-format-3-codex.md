## Summary

The two earlier data-loss inputs now preserve both runs: the fresh-store dictionary-key case and the same-timestamp pair written by 0.6.3. I found two other cases where the new parameter check permits an overwrite that the preceding implementation refused. Both require a mismatch between a file's name and its contents, a condition #27 explicitly promises to handle. Both reproduced entirely with files written by the current package.

## Findings in #27

The two versions ran the same script. Its labels refer to the storage format because both have the same package version. [Format 3 results](2026-11-23-hash-format-3-codex-evidence/current.txt) · [Format 2 controls](2026-11-23-hash-format-3-codex-evidence/previous.txt)

1. **Critical — replacing a file while preserving its modification time defeats the overwrite guard.** At `src/IOUtils.jl:160`, a matching path and modification time return the previous file's cached parameters. I saved A with field 10 and B with field 20, gave B the same modification time as A, warmed the lookup for A, then moved B over A. A direct JLD2 read confirmed that this path now held the sole copy of B. Saving A with field 30 and `overwrite=true` destroyed B. The format-2 save reopened the file and refused the overwrite. Read and validate the current stored identity before a destructive write, and invalidate cached reads across replacements, including changes that preserve mtime.
2. **Critical — the guard treats the Boolean `true` as the integer `1`.** At `src/IOUtils.jl:152`, `isequal` accepts these distinct normalized parameter sets even though their format-3 hashes differ. This case uses a cold lookup. I saved a Boolean run with field 20, placed that file under the integer filename, then saved the integer run with field 30 and overwrite enabled. Reading the original file showed that its parameters and field had both been replaced. Format 2 refused the overwrite. Check stored identity using the same type distinctions used to name runs, in addition to handling any actual hash collision.
3. **Major — one failed staging move hides other valid runs on retry.** At `src/DataManagement.jl:224`, the temporary filename extends the source basename, and the staging loop lacks rollback. I supplied a short filename and a legal 252-byte filename on a filesystem with a 255-byte component limit. Rehash moved the short file aside, then failed while staging the long one. Retrying left the short run invisible and its only copy in a `.tmp` file. Format 2 left both runs visible with zero temporary files. Allocate short, unique staging names and restore staged inputs if staging fails. Provide a recovery path for interrupted batches.
4. **Major — staging a symlink together with its target breaks a parameter-changing rehash.** At `src/DataManagement.jl:225` and `src/DataManagement.jl:236`, moving the target aside breaks a relative link to its old name before the rewrite reads it. Error recovery at line 248 tests `ispath`, which is false for the dangling link. I called `rehash_sim_data(dir; remove_keys=[:obsolete])` on one dataset and one relative symlink to it in the same directory. Only the target completed, and the link remained under a temporary name. Format 2 produced two readable outputs. Resolve the input link dependencies before staging and handle dangling links explicitly during cleanup.
5. **Minor — converting a directly constructed integer particle dataset now throws.** At `src/ConversionUtils.jl:124` the spacing calculation calls `_wide`, defined only for `AbstractFloat`. The public typed `DomainInfo{1,Int}` and `LSimData` constructors accepted particles at 0 and 1 with constant state 2. Converting to a two-node grid returned `[2, 2]` before #27 and now throws `MethodError` in `_wide`. Support the permitted real coordinate types in the widening step. The convenience constructors normally promote inputs to floating point.
6. **Minor — reading successive data folders retains deleted parameters for the life of the process.** At `src/IOUtils.jl:156` and line 163 the global parameter dictionary grows with each path. I read and deleted 16 runs, each in a different folder with a 64 KiB string parameter, switched to a fresh root and ran garbage collection. All 16 deleted paths remained, accounting for 1,057,879 additional bytes in the dictionary in this run. Bound the cache or scope it to the active index and evict deleted/replaced entries. The previous version had no such cache.

## Outside #27

- **Critical — cleanup can delete the only correct result.** At `src/DataManagement.jl:299`, `tidy_sim_data()` groups files solely by filename hash. I gave an A file and a misplaced B file the same filename hash and modification time. Before cleanup, format 3 correctly loaded A and its field 10. Cleanup then deleted A as a duplicate and left only B with field 20. Format 2 also deleted the only A file. The cleanup code is unchanged. Verify stored parameter identity and readability before classifying candidates as duplicates. [Version comparison](2026-11-23-hash-format-3-codex-evidence/README.md)
- **Major — native Float16 particle mass can be infinite when the correct answer is representable.** At `src/Constructors.jl:217`, the constructor computes the domain extent in Float16 before dividing by the number of particles. With particles at −40000 and 40000, each carrying density 0.25, the spacing should be 40000 and mass 20000. Both snapshots returned infinity for both quantities in Float16 and the expected finite values in Float32. #27 fixes the separate conversion path. Widen the extent and volume calculation before converting the resulting spacing back. [Native mass output](2026-11-23-hash-format-3-codex-evidence/native-mass.txt)
