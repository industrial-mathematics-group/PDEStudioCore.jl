## Findings

### 1. Post-processing is applied again to data it already changed, and the docs no longer require idempotence (medium, CONFIRMED)

- **Where:** src/Simulations.jl `_postprocess_record` / `_post_task`; docs/src/advanced_config.md §3; the `run_all_simulations` docstring; index.md ("run once on every dataset").
- **What:** The record contains the digests of *all* `config.sources`. Under the default `on_changed_sources = :warn` (and also `:ignore`), stored data is kept when a source changes, but the record no longer matches. So the post-processor runs again on data it already post-processed. The same happens:
  - with `force_postprocess = true`;
  - when the solver package's version changes;
  - once for every existing file on the first run after upgrading, because pre-commit files have no record.

  The old docs said "make the function idempotent". The new docs dropped that and say the pass "runs once per dataset", which invites post-processors that are not idempotent.
- **Evidence:** `probe_post_nonidempotent.jl`, with `double_post(d) = (d.u .= d.u .* 2; true)`:
  - first run u = 2, second run u = 2 (skipped, correct);
  - after a comment-only edit of the source file: u = 4;
  - after removing the record (a pre-commit file): u = 8.
- **Fix:** At minimum, keep the idempotence requirement in the docs and docstring, and say when the pass runs again (other sources or package version, `force_postprocess`, files without a record). Better: rerun only on new data unless the post-processor itself changed. For example:
  - keep the record's `"sources"` only when the data is recomputed;
  - or with `:warn`/`:ignore`, compare the record without `"sources"`.
- **Test:** a post-processor that is not idempotent; edit a comment in the source; run with `:warn`; assert the stored data is unchanged, or that the docs state the rerun.

### 2. Solvers and post-processors that are callable objects stopped working (medium, CONFIRMED, regression)

- **Where:** src/IOUtils.jl `_provenance` (`nameof(solver)`, `parentmodule(solver)`); src/Simulations.jl `_postprocess_record` (`parentmodule(post_func)`) and `_code_changed` (`parentmodule(solver)`).
- **What:** `resolve_dynamic_function` returns any global (`getglobal`), so a `const my_solver = MySolver(...)` functor is resolved by name, and the public `run_smart_simulation(sim_func, params)` accepts any callable. `nameof` and `parentmodule` have no methods for instances.
  - Solver case: the solver runs to completion, then saving throws. The result is lost and the task is reported failed (compute wasted).
  - Post-processor case: `_postprocess_record` sits outside any `try`, so the whole `run_all_simulations` throws after passes 1–2.
- **Evidence:** `probe_callable_old.jl`:
  - 2818d7e: "callable solver stored its result: true", "callable post-processor: ok".
  - a42a9e0: "false", "threw MethodError".
  - `probe_callable.jl` shows `MethodError: no method matching nameof(::LinSolver)` and `parentmodule(::Post)`.
- **Fix:** Use helpers such as `_func_name(f) = f isa Function ? nameof(f) : nameof(typeof(f))` and `_func_module(f) = f isa Function ? parentmodule(f) : parentmodule(typeof(f))`. Wrap the provenance and record collection in `try` so bookkeeping can never discard a finished result.
- **Test:** a functor solver and a functor post-processor through `run_all_simulations` (result stored, record written).

### 3. `save_sim_data(...; overwrite = true)` of the *same* data counts as new data, and `calculate_all_stats!` can write a file without provenance (low, CONFIRMED)

- **Where:** src/IOUtils.jl `save_sim_data` (always merges `_new_data_entries()`); src/StatCalculation.jl `_calculate_all_stats!` (`_save_sim_data(..., evaluated)` for a dataset not stored yet).
- **What:** The `calculate_all_stats!` docstring tells users to persist `add_stat!` values with `save_sim_data(data; overwrite = true)`. That rewrite:
  - replaces the provenance, losing `solver`, `solver_module`, `solver_version`, `wall_time`, the original host and the creation time;
  - drops `"postprocessed"`, so the next pipeline run post-processes again (which compounds F1).

  Separately, `calculate_all_stats!(data)` on a dataset that isn't stored yet writes a new file with no `"provenance"`. That contradicts "every data file also records its provenance" (advanced_config.md). Claim 5 lists `save_sim_data` among the writers that keep record entries on same-data rewrites; it doesn't.
- **Evidence:** `probe_record_writers.jl`:
  - after `save_sim_data(same; overwrite)`: `solver=nothing wall_time=false record=nothing`;
  - post-processor calls 1 → 2 on the next run;
  - `calculate_all_stats!` new file: `provenance=nothing`.
- **Fix:** In `save_sim_data`, carry the record over when the stored file holds the same solution (`_is_native_representation`), or at least keep the provenance. In `_save_sim_data`, add `_new_data_entries()` when no file exists yet. Document the behaviour in the `save_sim_data` docstring.
- **Test:** `add_stat!` + `save_sim_data(overwrite)` keeps `prov["solver"]` and the record; `calculate_all_stats!` on unsaved data writes a provenance.

### 4. `sim_data_table`: parameters named like a fixed column overwrite it (low, CONFIRMED)

- **Where:** src/DataManagement.jl `sim_data_table` (`row[Symbol(k)] = v` after the fixed columns; `setdiff(..., fixed)` removes the parameter column).
- **What:** A parameter `:solver`, `:kind`, `:file`, `:shape`, `:stats`, `:created`, … silently replaces the metadata column. The `file` column, which identifies the row, then shows the parameter value.
- **Evidence:** `probe_table.jl`: `solver column = "rk4"` (provenance says `lin_solver`); `kind column = "test"`; `file column = "mesh.msh"`. No downstream config uses these names (grep of HyperCloudDev and PDEStudio), so the risk is for users.
- **Fix:** Fill parameters first and the fixed columns last, and prefix colliding parameter columns (e.g. `param_solver`), or put parameters in a nested column.
- **Test:** a parameter named `:file` / `:solver`.

### 5. Data folder shared with an older PDEStudioCore: an old writer carries the new record onto new data (low, CONFIRMED)

- **Where:** the record design (`"postprocessed"` and `"provenance"` are plain top-level entries). Old `_write_sim_file` carries over every key it doesn't manage.
- **What:** If a 0.4.x / 2818d7e process replaces the data (`force_overwrite`, `post_process = false`, or a manual `save_sim_data(overwrite = true)`), it keeps the record and provenance of the previous data. The new version then skips post-processing of data that was never post-processed, and the provenance describes another run. This is plausible during the transition, e.g. cluster jobs pinned to an older Core writing into the folder PDEStudio reads.
- **Evidence:** `probe_mixed_versions.jl`:

  | Step | u[1] | Post-processor calls | Record | `provenance.created` |
  |:--|:--|:--|:--|:--|
  | new code | 101 | 1 | `mark_post` | T |
  | old code, force_overwrite, no post-processing | 2 | 0 | `mark_post` | T |
  | new code again | 2 | 0 (skipped) | `mark_post` | T |

- **Fix:** Old writers can't be changed, so document that mixed versions on one data folder need `force_postprocess = true` (release notes). Optionally, tie the record to the data, e.g. store `"shape"` and a cheap fingerprint of the raw dataset's position in the file in the record. Any plain marker key would be carried over by old writers just like the record.
- **Test:** none possible in-suite without the old version; a docs note is enough.

### 6. `dry_run` / `upgrade_sim_data(dry_run = true)` report differs from the real run (low, CONFIRMED)

- **Where:** src/Simulations.jl `_run_task` (`_is_current_file(path; upgrade = false)`) and the `would_run[i] ? (:ran, nothing)` shortcuts in passes 2 and 3; src/DataManagement.jl `upgrade_sim_data` dry-run branch.
- **What:**
  - A version-0 file whose data loads is reported "would run". The real run upgrades it and reports it cached.
  - For would-run tasks, statistics are reported `:ran` even when no statistics are registered. The real run reports `:cached`.
  - `upgrade_sim_data(dry_run = true)` lists a file whose `"raw"` doesn't load as `:upgraded`; the real call returns `:unreadable`.

  Writing nothing holds: names, mtimes and sizes were identical.
- **Evidence:** `probe_dryrun.jl`:
  - dry run: `ran=2 cached=2 stats=Dict(:ran => 2, :cached => 2)`;
  - real run: `ran=1 cached=3 stats=Dict(:cached => 4)`;
  - `upgrade_sim_data(fq; dry_run) = upgraded`, real `= unreadable`.
- **Fix:**
  - In a dry run, classify version-0 files by trying to load `"raw"` read-only, without writing.
  - Use `isempty(required) ? :cached : :ran` for would-run tasks.
  - In the `upgrade_sim_data` dry run, load `"raw"` and check `isa AbstractSimData`.
- **Test:** compare dry-run and real summaries on a folder with a version-0 file and an unreadable file.

## Claims verified without findings

The lock covers listing and storing; `_DataIndex` objects are never mutated after publication except by the test. `_write_sim_file` invalidates in `finally`; `delete_sim_data`, rehash and tidy invalidate. `_update_entries!` and upgrades don't rename, so they need no invalidation.
- **Provenance (claim 5):** carried over by statistics rewrites, post-processing rewrites (`true` path and record-only path), rehash and the conversion cache. Replaced by `run_smart_simulation` and `force_overwrite`. Reserved keys are refused as Symbol or String in `save_sim_data` and `run_smart_simulation`.
- **`_git_commit`:** correct for a detached linked worktree, a branch with packed-refs, and no repository (`probe_git.jl` plus the package's synthetic tests).
- **Changed code (claim 2):** solver-package version and source digests detected; moved sources and "no sources now" not flagged (`probe_solver_version.jl`).
- **`tidy_sim_data`:** removes exactly the files lookups don't use (same `_sort_newest!` key, including mtime ties). A live temp file from `cp` has a fresh mtime, so it is kept.

- **Hash stability:** Serialization.jl and the file naming are untouched, and `test_serialization.jl` passes.

## Breaking changes and downstream

- `run_all_simulations` returns `RunSummary` instead of `nothing`. No downstream code tests for `nothing`. HyperCloud's `@sim` (src/macros.jl:166) now returns and prints the summary at the REPL; harmless, worth a release note. PDEStudio `claude/release-qol` already uses the summary (src/PDEStudio.jl:390).
- New reserved metadata keys (`provenance`, `postprocessed`, `format_version`): no downstream use (grep of HyperCloudDev, PDEStudio src/test).
- No downstream use of the changed internals (`_run_task` etc.), except an old HyperCloud review probe (`reviews/a049a3a/hc/probe_examples.jl`), which is not part of any suite.
- Behaviour changes to list in the PR:
  - post-processors no longer run on every call (F1);
  - callable-object solvers are broken (F2, to fix);
  - `metadata` values of `nothing` are now dropped and delete an existing entry of that name (undocumented);
  - `does_sim_data_exist` now writes to version-0 files (upgrade);
  - mixed-version data folders (F5).

## Minor issues

1. **Index docs overstate it** (IOUtils.jl comment: "a missed change … can only cost time, never a result"; data.md: "Files added or removed by other processes are seen"). If another process adds a *newer duplicate* of a hash already in the index while the directory time looks unchanged (FAT's 2 s mtimes, which the 1 s racy window doesn't cover; NFS attribute caching), lookups return the older duplicate (`probe_index_stale_dup.jl`). Duplicates usually hold equivalent results, so either soften the wording or check the directory time against the newest listed file. The racy test also mixes the file-system clock with `time()`: a server clock ahead of the client only costs relisting.
2. **`dry_run` still includes `config.sources`**, i.e. runs their top-level code. The docstring and docs say "nothing is run or written"; say "no solver, statistic or post-processor runs".
3. **`RunSummary` docstring:** "`changed` … kept, recomputed or ignored". With `:ignore` the list is always empty because the check is skipped; say so.
4. **`sim_data_table` docstring** says "one row per stored run", but version-0 files (no `"params"` entry) are skipped silently.
5. **`_format_version`** uses `Int(file["format_version"])`. A 0.4-era user entry named `"format_version"` (it wasn't reserved then) that holds a non-integer throws inside `sim_data_table` and aborts the whole table.
6. **`_git_commit()`** uses the active project's folder. With the default global environment it may record an unrelated repository (e.g. a dotfiles repo in `$HOME`), and it doesn't flag uncommitted changes. Worth one sentence in the docs.
7. **data.md:** "Other metadata entries are stored as they are": except values of `nothing` (see Breaking changes).

## Verdict

Not ready to merge as is; fix F2 and F1 first. The index, the RunSummary counts, the changed-code detection, the git reading, tidy, and the guarantee that a dry run writes nothing all held up under probing. Tests pass at `-t 1` and `-t 8`, the docs build, and hashes are unchanged.

- **F2 (medium):** a real regression; small fix.
- **F1 (medium):** needs at least the idempotence requirement back in the docs, preferably narrower rerun conditions.
- **F3–F6 (low):** document or fix before release; F5 needs a release note.

Counts: 0 high, 2 medium (F1, F2), 4 low (F3–F6), 7 minor. All six findings CONFIRMED with probes in `$R/probes/`.
