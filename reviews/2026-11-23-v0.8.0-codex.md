## Findings in #36

1. **Critical. Import can install different bytes from those it validated.** At `src/DataManagement.jl:200`, the importer checks the original source. The plan at line 212 retains its path and parameters. At line 247, the byte-copy path reads the source's current bytes. I started with two valid source files and an existing complete destination for the first. The first prompt left its parameters alone. At the second prompt, I replaced the first source atomically with a copy whose `raw` entry was a string. The 0.8.0 batch reported two successful imports and replaced the first destination. The run still reported as present, but loading returned a `String`. The preceding snapshot copied the first source before the second prompt and preserved the complete destination in this sequence. Stage and validate the bytes that will be installed, and bind any parameter-changing rewrite to the dataset and metadata read from that same source version. A changed source should be reported before replacing its destination. [Current and previous outputs](2026-11-23-v0.8.0-codex-evidence/README.md)
2. **Minor. A parameter filter now loads the full solution for runs it excludes.** At `src/DataManagement.jl:200`, `_run_problem` reads `raw` at line 276 before line 207 applies the filter. For a one-million-node run excluded by `filter_pairs=Dict(:k=>"unmatched")`, a warmed invocation allocated 16,422,000 bytes. The preceding snapshot allocated 49,760 bytes for the same input, and both imported zero files. Read the lightweight parameters and apply the filter before validating the full dataset for selected runs. [Measurement](2026-11-23-v0.8.0-codex-evidence/current.txt) · [Control](2026-11-23-v0.8.0-codex-evidence/previous.txt)
3. **Minor. The linked-destination restriction is stated for the entire store, while it applies only to import.** At `src/DataManagement.jl:161` the docstring says the store does not write through links. Ordinary `save_sim_data(...; overwrite=true)` still writes through an existing link whose target holds the requested run, as implemented at `src/IOUtils.jl:335`. With target field 7 the save changed the external file to field 9 and kept the link. The preceding snapshot behaved the same way. Scope the restriction to imports and document what direct saves do to linked targets. [Version comparison](2026-11-23-v0.8.0-codex-evidence/README.md)

No findings in #37. The project and citation versions both say 0.8.0. No separate findings outside #36 and #37.
