## Findings in #50

1. **Critical. Distinct `Val` type parameters can resolve to the same run.** In `src/Serialization.jl:32–33`, stripping the module from a custom type inside `Val` can turn it into the name of an allowlisted type. I ran two single-task configurations with one solver. The solver returns 10 for `Val{Base.Matrix}()` and 20 for `Val{ParameterTypes.Matrix}()`, where the latter `Matrix` is a user-defined struct. Both tags normalize to `Val{Matrix}()` and get the same hash. The second configuration reports `:cached` and reads 10. On the first parent, the second type has a qualified tag, uses a different hash and returns 20. Preserve the identity of nested user types in the canonical encoding, or reject values whose identities the format cannot represent. Test distinct single-run configurations against a shared store and account for previously stored qualified tags. [Normalization](../src/Serialization.jl#L27) · [Head](2026-11-24-main-c45656d-codex-evidence/head.txt) · [First parent](2026-11-24-main-c45656d-codex-evidence/base.txt)
2. **Major. A reference refresh can relabel an older statistic as current.** `src/Simulations.jl:390–396` refreshes the active statistic names and updates the file-wide reference record. `src/StatCalculation.jl:213–226` keeps saved values whose names were removed from the global registry. I computed L1 against reference A, then edited the reference to B, unregistered L1 globally, and registered L2. The run reported `:refreshed` and recorded B, while keeping L1 = 2 from A. Re-registering L1 produced `:cached` and still returned 2. The correct L1 against B is 6. The first parent still reports this combination as `:outdated` against B. When the file-wide record changes, invalidate previously evaluated values that were skipped during the refresh, or track reference provenance per statistic. Preserve independently attached statistics in either approach. [Refresh](../src/Simulations.jl#L375) · [Registry](../src/StatCalculation.jl#L211) · [Head and first-parent output](2026-11-24-main-c45656d-codex-evidence/README.md)
3. **Minor. A dry run logs a completed refresh.** `src/Simulations.jl:392–393` returns the new `:refreshed` status during planning, and `:710–713` logs that the values “were evaluated again.” I ran the preceding reference scenario with `dry_run = true` and confirmed the file remained byte-identical while the warning claimed the refresh completed. Report a planned refresh in this mode. [Warning](../src/Simulations.jl#L710) · [Head output](2026-11-24-main-c45656d-codex-evidence/head.txt)

## Outside #50

1. **Major, original regression persists in caches written by #48.** I created the mixed A/B file on the first parent, restored reference A, and opened the same store on #50. The run with `:recompute` reported `:cached` and returned L2 = √18 instead of √2. The stored record already matches A. A run with `force_stats = true` repaired it. The bad cache was created before #50. Document the recovery for existing files or invalidate the affected provenance records when reading them. [Two-version output](2026-11-24-main-c45656d-codex-evidence/legacy.txt)
2. **Minor. The hash of a type from a module named with a mathematical symbol can still depend on imports.** Julia accepts `module ∇Tags`. On both revisions the text of its `GradientTag` changed from `Main.∇GradientTag` to `GradientTag` after the unqualified import, and its hash changed with it. Qualification should follow Julia identifier syntax. The earlier Greek-letter module case passes. [Normalizer](../src/Serialization.jl#L11) · [Head and first-parent output](2026-11-24-main-c45656d-codex-evidence/README.md)
3. **Minor. The weighted scatter can still overflow at large Float64 magnitudes.** On both revisions, one particle on its output grid node with state `1.0e300` produced `Inf`. Its exact one-sample average is `1.0e300`. The weight is applied before division, so the intermediate product overflows even with Float64 accumulation. Scaling the weights or computing a weighted mean without the large intermediate product addresses this case. [Scatter](../src/ConversionUtils.jl#L75) · [Head and first-parent output](2026-11-24-main-c45656d-codex-evidence/README.md)
