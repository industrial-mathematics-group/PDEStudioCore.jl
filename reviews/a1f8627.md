## Findings

### 1. Medium — CONFIRMED — Chains carried across bracket levels still overflow `Meta.parse` (16 KB)

- **Where:** `_too_nested`, `src/Serialization.jl:274-297`. A closing bracket does `terms = pop!(outer) + 1`, and only the count of the current level is compared with `_MAX_TERMS`.
- **What goes wrong:**
  - Each bracket level may hold up to 1024 tokens, and up to 32 levels may be open.
  - A chain with about 511 links per level, nested 16 deep, gives an Expr about 8000 levels deep, while no level ever exceeds the limit.
  - JuliaSyntax's `node_to_expr` recurses once per level and overflows. It logs "JuliaSyntax parser failed — falling back to flisp!", the flisp parser takes over, and `str2val` returns a String after about 0.8–1.4 s.
  - This is the same crash class the commit says it closes, reached through the per-level reset.
- **Evidence:** `probes/probe_new_attacks.out`, `probe_more_families.out`, `probe_thresholds.out`, `probe_where_overflow.out`. `levels(L, head, tail)` is defined in `probes/gen_lit.jl`: L times `"(" * head * inner * tail * ")"`, starting from `"1"`. `_too_nested` is `false` for every text below.

  | Text | Size | Result |
  |:--|:--|:--|
  | `levels(16, "1^"^511)` | 16 KB | StackOverflowError (main thread and `Threads.@spawn`), String |
  | `levels(14, "1^"^511)` | 14 KB | no overflow (threshold between 14 and 16 levels) |
  | `levels(31, "a->"^511)`, `levels(31, "1=>"^511)` | 47 KB | StackOverflowError, String |
  | `levels(31, "", "-1"^511)` (left-assoc), `levels(31, "", "'"^1022)` | 31 KB | StackOverflowError, String |
  | `levels(31, "- "^1022)`, `levels(31, "!"^1022)`, `levels(31, "√"^1022)` | 31–63 KB | StackOverflowError, String |
  | `levels(31, "", " where T"^511)`, `levels(31, "", "::T"^511)` | 31–63 KB | StackOverflowError, String |

- **Fix:** bound the tokens along the whole path of open brackets, not only the current level. For example, keep `open = sum(outer)` up to date on push and pop, and reject when `open + terms > _MAX_TERMS`. `val2str` output stays far below that: each outer entry holds only the few tokens since the last comma (`Any`, `Dict{…}`, `reshape`), so 32 levels × a few tokens.
- **Test:**
  - `@test T(levels(16, "1^"^511))`, `@test T(levels(31, "", "'"^1022))` and `@test T(levels(31, "- "^1022))`, with `levels` as above
  - keep `!T(val2str(Any[Any[…]]))` with 30 levels and long element lists

### 2. Low — CONFIRMED — Assignment operators and macros nest through commas, which reset the count (60–70 KB)

- **Where:** `_too_nested`, `terms = 0` on `K","`.
- **What goes wrong:** the check assumes a comma ends a nesting chain. Two constructs nest through commas anyway:
  - **Assignment-precedence operators** bind more loosely than `,` at the top level. `a = b, c = d` parses as `a = ((b, c) = d)`. The same holds for `op=`, `.=`, `:=`, `~`, `.~`, `≔`, `⩴`, `≕` (`probe_separators.out`).
  - **Macro calls without brackets** take the rest of the comma list as arguments, at the top level and inside `(`, `[` and `f(`. With 50 repetitions, `@a 1, @a 1, …` has depth 100 (`probe_macro_comma_depths.out`).
- **Evidence:** `probes/probe_new_attacks.out`, `probe_thresholds.out`, `probe_macro_comma.out`. `_too_nested` is `false` for every text below.

  | Text | Overflows at | No overflow at |
  |:--|:--|:--|
  | `"x = 1, "^n * "1"` | n = 10^4 (70 KB), also in `Threads.@spawn` | n = 7000 |
  | `"x += 1, "^n`, `"x ~ 1, "^n`, `"x := 1, "^n` | n = 10^4 | |
  | `"@a 1, "^n * "1"` | n = 10^4 (60 KB) | |
  | `"[" * "@a 1, "^n * "1]"` | n = 10^4 | |

  Each case logs StackOverflowError plus the warning, then returns a String after 0.8–2.4 s.
- **Fix:**
  - Refuse `K"@"` outside strings. `val2str` writes no unquoted `@`: `repr(Symbol("@a")) == "Symbol(\"@a\")"`.
  - Refuse assignment-precedence tokens (`_JS.is_prec_assignment(k)`, present in 1.12's JuliaSyntax too), or don't reset the count at commas at bracket level 0.
  - `val2str` writes `=` only inside struct, NamedTuple and `Pair(first=…)` texts. Both parsers return those as Strings (parity rows 72–85, 95, 123), so refusing changes no hash text.
- **Test:**
  - `@test T("x = 1, "^2000 * "1")`, `@test T("x ~ 1, "^2000 * "1")` and `@test T("[" * "@a 1, "^2000 * "1]")`
  - keep the `!T(val2str(...))` guards

## Minor issues

- **Internal API.** None of `Base.JuliaSyntax`, its `Tokenize` module, `kind`, `is_whitespace`, `is_keyword` or `K"…"` is public (`Base.ispublic(Base, :JuliaSyntax) == false`; `JuliaSyntax.tokenize`, which parses, is the exported one).
  - Everything used exists with the same meaning in the JuliaSyntax that 1.12 pins (46723f0 for v1.12.0, 29ec522 for release-1.12):
    - `Tokenize.tokenize(x) = Lexer(x)`
    - `kind(::RawToken)` extends `JuliaSyntax.kind`
    - `is_whitespace` covers `Whitespace`, `NewlineWs` and `Comment`
    - the keyword range covers `var` and the contextual keywords, with `Bool` outside it
    - `EndMarker`
  - One version difference: 1.12's `RawToken` has a `dotop` flag (`.+` is one token), while 1.13 lexes `.` separately (`probe_kinds.out`: `.=` → `.`). Token counts of dotted operators therefore differ by version, which is negligible at a limit of 1024.
  - A comment naming the internal dependency would help, or a fallback that refuses (returns `true`) if `Base.JuliaSyntax.Tokenize` is missing on some future Julia.
- **The docstring says "more than 1024 tokens between two commas".** The code also resets at `;` and counts per bracket level. The comment says "a block keyword (`begin`, `if`, …)", but every keyword except `var` is refused, contextual ones (`type`, `as`, `doc`, `outer`, `public`, …) included. Since such texts are never literals, this changes no behaviour.
- **`_too_nested` can throw.** `Tokenize` raises `InvalidCharError` on an identifier followed by an overlong UTF-8 sequence (`"x\xc0\x8f"`). `str2val`'s `try` turns that into the same String the reference returns, and it even avoids the reference's logged JuliaSyntax error and flisp fallback. Only callers of `_too_nested` outside `str2val` would see the exception; there are none (`grep`).
- **`docs/src/data.md` overclaims.** It says "these limits bound what the parser computes and compiles for a text". Time stays bounded (≤ 2.4 s), but Findings 1–2 still reach a stack overflow.
- **`;` inside calls** (`Dict(1; 1; …)`) builds an Expr 10^5 levels deep (nested `parameters`) without an overflow. `_literal` bounds it. Noted only because it is the remaining case of deep nesting without a token count.
- **Unmatched closing brackets reset the count to 0** (`isempty(outer) ? 0`). `("1^"^511 * "1)")^100` doesn't overflow, because the parser stops at the first unmatched `)`. Harmless.
