## Findings

### 1. Low — CONFIRMED — `_may_hide` is recomputed on every visit and not counted in the budget, so the per-entry bound does not bound the cost
- **Where:** `src/IOUtils.jl:199-203` (the `_may_hide(keytype/valtype/eltype(value))` calls in `_reconstructed_type`) and `src/IOUtils.jl:215-223` (`_may_hide`).
- **What:**
  - The budget counts visits (10^5), and the memo `state.seen` caches only the string check.
  - `_may_hide(eltype(value))` is called again for every container visited. It recurses through `fieldtypes` up to 4 levels, so it costs up to (field count)^4 calls, each allocating.
  - The comment ("its cost is bounded per entry: at most 10^5 values are visited") and the commit message suggest a constant bound. In fact the cost is (number of visits) × (size of the element type).
  - The budget also went from 10^4 to 10^5, so on such inputs bc0e729 is slower than 64a39da.
- **Scenario:** contrived, but it is a user entry: an `Any` vector of many containers whose element type is a wide or nested tuple or NamedTuple type, e.g. per-run records stored as `Vector{NTuple{…}}` or `Dict{Symbol, NamedTuple{…}}`. Each rewrite of the data pays the check again.
- **Evidence:** `probes/probe_reconstructed3.out`, `probes/probe_mayhide_*.out`:

  | Case | bc0e729 | 64a39da |
  |:--|:--|:--|
  | `Any[10^5 × Vector{NTuple{10, NTuple{10, NTuple{10, Float64}}}}()]` | 16.7 s, 3.7 GiB | 1.9 s, 0.7 GiB |
  | `Any[10^5 × Dict{Symbol, NTuple{20, NTuple{20, NTuple{20, Float64}}}}()]` | 88 s, 23.7 GiB | 1.0 s, 0.6 GiB |
  | `Any[10^4 × [NTuple{100, Float64}]]` | 52 ms | 1720 ms |

  The realistic sizes in the last row got faster.
- **Fix:** memoize `_may_hide` per type in `state`, e.g. `get!(() -> _may_hide(T), state.hides, T)` with a `Dict{Any, Bool}`, or in a global `IdDict`, since the result depends only on `T`. The cost per entry is then bounded by visits plus (distinct types × type size). Optionally, also memoize `_may_hide`'s own recursion, since the same field type repeats in `NTuple`s.
- **Test:** `v = Any[Dict{Symbol, NTuple{20, NTuple{20, NTuple{20, Float64}}}}() for _ in 1:10^5]; _reconstructed_type(v); @test @elapsed(_reconstructed_type(v)) < 0.5` (88 s now).

### 2. Low — CONFIRMED — `Set`s (and other `AbstractSet`s) are still not entered
- **Where:** `src/IOUtils.jl:199-203`. Only `AbstractDict`, `Pair`, `Tuple`/`NamedTuple` and `AbstractArray` are entered, and `_may_hide` knows the same four families.
- **What:** finding 1 of 64a39da listed "NamedTuple, Pair and **Set**". NamedTuple and Pair are fixed. `Set{Any}` is still missed at top level, nested (`Dict{Symbol, Any}(:s => Set{Any}([h]))`) and end to end. The commit message mentions only NamedTuples and pairs, so this item is silently dropped.
- **Scenario:** user metadata such as `Dict(:solvers => Set{Any}([SomeType]))`. The next rewrite stores the reconstruction with only JLD2's generic line.
- **Evidence:**
  - `probes/probe_reconstructed2_part1.out`: "Set{Any}" → `nothing`; "Set{Any} in Dict{Symbol,Any}" → `nothing`.
  - `probes/probe_reconstructed3.out`, end to end: the warned entries are `box`, `nested`, `nt`, `top` and `vv`, **not `set`**.
- **Fix:** treat `AbstractSet` like arrays: `value isa Union{AbstractArray, AbstractSet} && _may_hide(eltype(value))`, and add `AbstractSet` to the families in `_may_hide`. Alternatively, say in the comment that sets are not inspected.
- **Test:** add `st = Set{Any}([H])` to the `jldsave` / `for k in (…)` loop in `test/test_data.jl:130-134`.

### 3. Low — CONFIRMED (crafted files) — The validation of stored axes accepts user entries that look like axes, and the `:missing` sentinel is a valid axis name
- **Where:** `src/IOUtils.jl:373-387`.
- **What:** the rule is `dim_keys isa AbstractVector{Symbol}`, `time_dim` is `nothing` or a Symbol `in dim_keys`, and, for Eulerian data, `length(dim_keys) == length(shape)`. Four gaps:
  - **(a)** It does not require the time key to be **last**, although every file this version writes has it last (enforced by `DomainInfo`).
  - **(b)** For Lagrangian data, the number of keys is not checked at all.
  - **(c)** A static grid with user entries `[:x, :t]`/`:t` is reported as transient, with `n_steps = shape[end]`.
  - **(d)** A missing `"time_dim"` entry is read as `:missing`. Together with a user `"dim_keys" => [:missing]` (or any vector containing `:missing`), that passes the check and returns `time_dim = :missing`.

  On the question in the brief: **the rule never rejects what bc0e729 writes itself.** All 10 data kinds, overwrite, rehash and the layout change take the fast path (31 checks in `probe_info.out`).
- **Scenario:** unlikely. It needs a file written before November 2026 whose user metadata used these names with Symbol values that look like axes. No code under `/workspace/julia` stores such entries.
- **Evidence:** `probes/probe_info.out`, section "crafted 'older files'":
  - `(:u, :v)`/`:v`, `(:t, :x)`/`:t`, static `(:x, :t)`/`:t` with `n_steps = 3`, Lagrangian `(:a,)`/`:a`: all trusted.
  - `[:missing]` without a `"time_dim"` entry gives `time_dim = :missing`.
- **Fix:**
  - Require `time_dim === nothing || (!isempty(dim_keys) && dim_keys[end] === time_dim)`. That is exactly the `DomainInfo` invariant.
  - Read the two entries with a sentinel that can't be a Symbol, e.g. `haskey(file, "time_dim") || (valid = false)`, or `tdim = … : missing`.
  - Optionally require `allunique(dim_keys)`.
  - The remaining residual (Symbols that look exactly like axes) can't be detected without loading the data. Accepting it is fine, but the comment could say so.
- **Test:** extend the new user-metadata test in `test/test_data.jl:294-300` with `f["dim_keys"] = [:t, :x]; f["time_dim"] = :t`, and a variant with `[:missing]` and no `"time_dim"`, each expecting `info`.

## Minor issues

- **The memo is per call, and `string(T)` costs 0.1–0.25 ms per distinct type.** This is pre-existing. An entry with thousands of distinct types (e.g. 2000 NamedTuples with different field names: 237 ms, `probes/probe_cost_types_new.out`) costs time proportional to that number, up to 10^5 × 0.25 ms. Detecting the markers on `T` structurally (`T.name.module === JLD2` and the parameters) instead of printing would avoid it. That was already suggested last time.
- **The shared budget makes detection depend on order:** a 10^5-element sibling before the hidden value in the same tuple, or 10^5 tiny `Any[]`s, exhaust it, so the later value is not checked. This is consistent with the documented bound; just noting it.
- **The commit message says "now 6 ms"**; I measured 2.1 ms. That is fine.
- **`_may_hide`'s docstring-comment** ("Whether elements of type `T` can be (or contain) values of other types than `T` says") reads awkwardly, but is accurate.
