## Findings in the reviewed changes

1. **Critical in #46. Removing module prefixes also edits data inside quoted type parameters.** At `src/Serialization.jl:14` and `:45`, the regex rewrites the printed forms of both `Val{Symbol("left.mode")}` and `Val{Symbol("right.mode")}` as `Val{:mode}`. These are different parameter values in the supported `Val` type grammar. I ran two separate configurations with a shared solver that returns 10 for the first type and 20 for the second. The new code hashed them alike, reported the second as cached, and returned 10. The first parent preserved the types, generated distinct hashes and returned 20. The new sweep collision check only compares tasks within one configuration. Normalize module qualification structurally or tokenize type text so that quoted symbols and other literal values are preserved, and verify both lookups and writes with the one-run configurations. Account for the affected files under the existing hash format. [Head](2026-11-24-v090-codex-evidence/head.txt) · [First parent](2026-11-24-v090-codex-evidence/base.txt)
2. **Major in #46. Post-processing removes a statistic the callback just computed.** At `src/Simulations.jl:475`, the deletion is based on names from the prior statistics pass. That list also contains statistics whose results were all NaN and were dropped. With no configured reference, the first pass recorded `:l1error` as evaluated and kept no value. The post-processor set the two solution nodes to 2 and attached an L1 error of 2 against its own reference value of 3. The head saved the field but deleted the new error. The next normal run skipped the post-processor and still had no error. At the first parent both runs load the callback's value of 2. Capture the pre-callback values as well as their provenance, or explicitly track the statistics the callback writes so that only the old results are invalidated. [Head](2026-11-24-v090-codex-evidence/head.txt) · [First parent](2026-11-24-v090-codex-evidence/base.txt)
3. **Minor in #46. Adding one statistic bypasses the new reference retention policy.** At `src/Simulations.jl:386–387`, `:warn` keeps the old values only if all required statistics are already present. I edited the reference from 2 to 4 for a unit field on two nodes. The same-registry run reported `:outdated` and retained the old L1 error of 2. Registering mass made the next run recompute the old error as 6 with default `:warn`, contrary to `docs/src/advanced_config.md:140`. The first parent always recomputed on a reference edit, so the gap concerns the new policy. Apply the configured reference policy independently of registry expansion, or explain the exception and report when existing stats are refreshed. [Head](2026-11-24-v090-codex-evidence/head.txt)
4. **Minor in #46. The data guide says an incomplete destination is replaced on import.** At `docs/src/data.md:166`, the guide still promises replacement of an unusable file with matching parameters. I copied a complete source outside the store and removed only `raw` from its destination. Import returned zero results and the destination was byte-identical. The first parent replaced it. The current behavior agrees with the API docstring and the refusal implemented at `src/DataManagement.jl:207–217`. Update the guide to tell the caller to move or delete the unusable destination before retrying. [Head](2026-11-24-v090-codex-evidence/regressions.txt) · [First parent](2026-11-24-v090-codex-evidence/regressions-base.txt)

## Outside the new behavior

**Major, still open after the #46 fix. A changed large field can keep stale statistics.** At `src/Simulations.jl:491`, Julia's general array hash samples large arrays. I saved a 50,000-node field with values 1 through 50,000. The post-processor changed only the first node to 101. On Julia 1.13.4, the saved mass stayed at 1,250,025,000 and the next normal pass reported `:cached`. An independent sum over the loaded field gave 1,250,025,100. Both commits kept the stale result. At the head the new change detector misses the edit. Use a comparison or digest that accounts for every solution entry and its coordinates. [Head](2026-11-24-v090-codex-evidence/head.txt) · [First parent](2026-11-24-v090-codex-evidence/base.txt)

## Checks against the previous review

- Removing an unused key from an external run preserves the source bytes, the processed field of 11, the iteration diagnostic of 23 and the completion record. A reference factory that pops a parameter sees a copy. The requested field becomes 11 after post-processing, and the unrelated field stays 80.
- A rewrite preserves an unmanaged calibration value, its units attribute and an empty group. Adding an attribute to the group makes the rewrite fail and preserves the complete original file. The package regression also verifies that a failing custom writer leaves the source byte-identical.
- The new contract removes interactive parameter changes and limits key removal to keys that did not affect the results. Typed integer and rational data are now rejected. Floating-point constructors and the Float16 overflow controls pass. The earlier limitation for data already saved with infinite spacing still requires a solver rerun.
- The suite verifies that top-level symbolic links at canonical paths are refused and that import reads supported external sources. All reproduction runs used a single writer and ordinary package files. [Verification output](2026-11-24-v090-codex-evidence/regressions.txt)
