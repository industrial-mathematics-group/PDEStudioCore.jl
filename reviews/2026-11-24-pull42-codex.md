## Findings in #42

1. **Major. Import forgets that the saved solution has already been post-processed.** At `src/DataManagement.jl:280`, changing parameters clears the post-processing record while keeping the field produced by that post-processor. I used a solver returning 10 and a callback that added 1. After removing an unused parameter with `import_sim_data`, both source and destination held 11. The next default run reused the destination, ran the callback again and stored 12. At the first parent the callback was skipped and the field stayed 11. Preserve enough history to flag an already-processed field and require explicit replay or a fresh solver result. Statistics can still be invalidated independently. [Head](2026-11-24-pull42-codex-evidence/head.txt) · [Base](2026-11-24-pull42-codex-evidence/base.txt)
2. **Major. The widened mass calculation can turn an exact integer result of 1 into 0.** At `src/StatCalculation.jl:80–84` and `presets/hyperbolic.jl:22`, both the measure and field pass through floating-point arithmetic before the result is converted back. I constructed an `ESimData` with integer field values `[2^53 + 1, -2^53]` on two unit-spaced nodes. Both values and their sum fit in Int64. The old preset returned 1. The new preset rounded the first input down and returned 0. Widen low-precision floating-point data while preserving exact arithmetic for integer and rational inputs. The floating-point convenience constructor does not exercise this typed-constructor path. [Exact arithmetic case](2026-11-24-pull42-codex-evidence/exact.jl)
3. **Major. Reference grids can record zero spacing between distinct rational nodes.** At `src/ConversionUtils.jl:19`, the new spacing helper converts both endpoints to floating point before subtracting. I passed a `DomainInfo{1,Rational{Int}}` over `[10^16, 10^16 + 1]` to `generate_reference_simdata`. The two generated coordinates still differ by exactly 1. The stored spacing changed from `1//1` at the base to `0//1` at the head, giving a zero integration measure. Even the four-node grid on `[0,1]` no longer records exactly `1//3`. Keep the coordinate difference and division exact for rational coordinates and retain the widened calculation for Float16. [Head](2026-11-24-pull42-codex-evidence/head.txt) · [Base](2026-11-24-pull42-codex-evidence/base.txt)
4. **Minor. The new import documentation overpromises which statistics return.** `docs/src/data.md:151` and `src/DataManagement.jl:160` say the pipeline evaluates the dropped statistics again. A solver attached an iteration count of 23 with `add_stat!`. After removing an unused parameter and running with `calculate_stats=true`, the registered mass returned. The solver was cached and the iteration count was absent. The base retained it. Document that rerunning statistics restores registered calculations only and that solver-only diagnostics may require the original file or a solver rerun. [Reproducer](2026-11-24-pull42-codex-evidence/check.jl)

## Outside #42

- **Critical. A reference factory can redirect post-processing to another run.** At `src/Simulations.jl:372`, the factory receives the batch's live task dictionary. My factory used `pop!(p, :offset)` to take its reference parameter. Pass 3 looked up the mutated dictionary at line 662 and applied a normal field-changing callback to a separately stored run outside the configuration. Its field changed from 80 to 81. The requested run stayed at 10, the summary lost its offset and post-processing reported success. Both commits behave identically. Give reference factories a deep copy of the parameters, as the solver already receives. The guard added in #42 works when the post-processor itself changes the parameters. [Head and base instructions](2026-11-24-pull42-codex-evidence/README.md)
- **Critical. An ordinary rewrite silently loses user JLD2 attributes and empty groups.** At `src/IOUtils.jl:319–324`, the group path copies children only, and the dataset path assigns its decoded value to a new entry. I stored a calibration of 47 with the attribute `units="kelvin"` and an empty `pending_measurements` group. A metadata-only edit followed by `save_sim_data(...; overwrite=true)` retained 47, lost its units and removed the group. Both commits did this without a copy error. Recreate the groups and preserve the user attributes, or fail before replacing an original whose contents cannot be preserved. This is a separate path from the failing custom writer fixed by #42. [Head](2026-11-24-pull42-codex-evidence/head.txt) · [Base](2026-11-24-pull42-codex-evidence/base.txt)

**Existing Float16 data.** I also wrote an affected run with the first parent, then opened that same 0.8.0 store with the head. A normal run kept the cached infinite mass. Forcing statistics still used the infinite spacing already persisted in the raw dataset. Rerunning the solver with `force_overwrite=true` rebuilt the spacing at 40000 and the mass at 30000. This is a recovery limitation for previously stored data. [Upgrade experiment](2026-11-24-pull42-codex-evidence/stored.txt)
