## Findings in #48

1. **Major. A newly registered error statistic can stay cached against the wrong reference.** In `src/Simulations.jl:386–396`, the `:warn` path evaluates missing statistics with the current reference but writes the old reference record for the entire file. On two unit-valued nodes, I ran L1 error against reference A (constant 2), edited the same reference file to B (constant 4) and added L2 error. The intermediate run reported `:outdated`, kept L1 at 2 and computed L2 as √18. I then restored the exact bytes of A. Even with `on_changed_sources = :recompute`, the next run reported `:cached` and returned L2 = 4.242640687119285. L2 against A is 1.4142135623730951. The first parent recomputed both errors on restoration. Track reference provenance per statistic, or explicitly mark mixed-reference results so the file cannot be taken as current for one reference. Add a regression that restores A after registering a second error statistic under B. [Statistics pass](../src/Simulations.jl#L375) · [Reference record](../src/StatCalculation.jl#L291) · [Head output](2026-11-24-main-8b86a74-codex-evidence/head.txt) · [First-parent output](2026-11-24-main-8b86a74-codex-evidence/base.txt)
2. **Minor. The post-processing guide still describes a saved solution change.** `docs/src/advanced_config.md:77` now says changing the solution fails, then tells callers to return `true` for changed data and says that stored statistics are not recomputed after a post-processor changes the solution. A callback that changes `u` and returns `true` fails and leaves the file unchanged, as the regression at `test/test_store.jl:406` verifies. Describe the successful save in terms of statistics and metadata and remove the sentence about statistics after a solution change. [Guide](../docs/src/advanced_config.md#L77) · [Regression](../test/test_store.jl#L406)

## Outside #48

These issues reproduce at the first parent. They are findings in the full package snapshot.

1. **Minor. Importing a type from a Unicode-named module changes its cache key.** `src/Serialization.jl:15` only strips module qualifications that match ASCII identifiers. The same type parameter printed as `Main.ΔReview.UnicodeTag` before `using .ΔReview: UnicodeTag` and as `UnicodeTag` after it, producing different hashes in both revisions. This can make a stored run unavailable to an otherwise equivalent session. Normalize Julia module identifiers while preserving quoted literal values. Include an import-before/after test with a Unicode module. [Normalizer](../src/Serialization.jl#L11) · [Head and base results](2026-11-24-main-8b86a74-codex-evidence/README.md)
2. **Minor. Particle scatter can overflow when the interpolated value is representable.** At `src/ConversionUtils.jl:79–85` and `:146–149`, `Float32` accumulation multiplies an on-node sample by a weight of about 10¹² before dividing it back out. Converting a single particle at its output grid node with state `1.0f30` returns `Inf` on both revisions. The exact one-sample weighted average is the input. Normalize or scale the weights before accumulating the state, or use a wider accumulator for `Float32` and test finite large-magnitude data. [Scatter](../src/ConversionUtils.jl#L75) · [Head and base results](2026-11-24-main-8b86a74-codex-evidence/README.md)
