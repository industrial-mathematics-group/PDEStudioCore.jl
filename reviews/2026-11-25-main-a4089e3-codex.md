## Findings in #70

1. **Critical. A post-processor can accidentally claim and delete a legacy solver statistic.** `src/SimData.jl:212–213` logs a name without the dataset that received the write. `src/Simulations.jl:507–525` then uses that log to assign ownership on the dataset being post-processed. I prepared a 0.9 file whose solver attached `calibration = 47`. The current callback wrote `calibration = 99` on a separate scratch dataset and added `quality` to the actual run. It never touched the stored calibration. #70 nevertheless assigned the run's `calibration` to the post-processing layer. A later statistics refresh removed 47 from disk. The first parent preserved it with the same sequence. Track ownership against the actual target dataset and record successful assignments only. The tracker should also be isolated between callbacks. [Write tracker](../src/SimData.jl#L209) · [Adoption](../src/Simulations.jl#L501) · [Current output](2026-11-25-main-a4089e3-codex-evidence/ownership-head.txt) · [First parent](2026-11-25-main-a4089e3-codex-evidence/ownership-base.txt)
2. **Minor. A valid statistic name can interfere with missing-method detection.** At `src/StatLayers.jl:115–122`, `which` probes the ordinary name `:__no_statistic__` to identify the fallback method. I implemented a five-argument reference statistic under that name before the first run. #70 reported that it had no implementation. In the same session, another name with no method reported `:cached` without a reference. The first parent runs the implemented reference statistic. Identify the generic fallback by its method signature at definition time, independently of names that callers can register. [Classifier](../src/StatLayers.jl#L113) · [Output](2026-11-25-main-a4089e3-codex-evidence/fallback-name.txt)

## Existing findings in the whole-codebase snapshot

1. **Major, introduced in #68. A callback that assigns `data.stats` can erase another post-processor's result.** `src/Simulations.jl:499` retains the old dictionary across the callback. At `:531` it looks there for new names, and at `:553` it restores other callbacks' results into that dictionary. I ran one callback producing `:first_post` and another that assigned `data.stats = merge(copy(data.stats), additions)` to add `:second_post`. The second callback reported `:ran`. The saved `:first_post` disappeared, and `:second_post` appeared in the simulation layer with no owning post-processor. The first parent reproduces the same loss. Read the current backing dictionary after the callback or preserve the existing backing dictionary when assigning through the public setter. [Callback path](../src/Simulations.jl#L495) · [Output](2026-11-25-main-a4089e3-codex-evidence/assign-head.txt)
2. **Major, residual #68 migration issue. A direct 0.9 upgrade works, while a run already saved by the initial 0.10 implementation can still lose mass.** On the initial 0.10 implementation, I loaded a 0.9 file without the preset, edited only its metadata and saved. It persisted the earlier mistaken classification of mass as reference-dependent. At `src/StatLayers.jl:192`, an existing layer record bypasses migration. On #70 a reference change with the preset installed and only L1 registered deleted the mass. Opening an unmodified copy of the original 0.9 file on #70 preserved it. Add a way to handle records already migrated with the early 0.10 rule or document how users of those snapshots can restore affected statistics. [Migration](../src/StatLayers.jl#L191) · [Upgrade output](2026-11-25-main-a4089e3-codex-evidence/legacy-upgrade.txt) · [Direct-upgrade control](2026-11-25-main-a4089e3-codex-evidence/legacy-upgrade-control.txt)
3. **Minor, residual #68 guard issue. A scalar and a one-element series can have identical fingerprints.** At `src/StatLayers.jl:172–182`, a one-component `SVector` and a one-element vector of `SVector` have the same encoded size, length and bytes. I changed a scalar solver statistic `47` to `[47]` through the callback's dictionary view. The callback ran successfully and persisted a series under a key registered with no kept dimensions. This also occurs on the first parent. Include the representation kind in the fingerprint, or validate the resulting value against its kept dimensions. [Digest](../src/StatLayers.jl#L171) · [Output](2026-11-25-main-a4089e3-codex-evidence/stat-kind-head.txt)
4. **Minor, pre-existing numerical limits. Computing the integration measure first can still overflow or underflow L2 norms.** At `src/StatCalculation.jl:81–82` the product is computed in Float64 for Float64 data. With a two-dimensional four-node field of `1e-150` and spacings `1e200` on both axes, the measure is already infinite before the new rescaling starts. I got `Inf` for a norm of `2e50`. Spacings `1e-200` and values `1e150` yielded zero for a norm of `2e-50`. A one-node subnormal intermediate also exaggerated the norm by about 40 percent because it rounded to a nonzero value, which bypasses rescaling. All three reproduce on the first parent. The original single-axis weighted overflow now passes. Scale the integration measure before multiplying its factors, and detect subnormal intermediate terms. [Measure and scaled norm](../src/StatCalculation.jl#L79) · [BigFloat controls](2026-11-25-main-a4089e3-codex-evidence/l2-head.txt)
