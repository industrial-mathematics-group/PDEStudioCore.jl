## Summary

The original string sweep, Float16 example, reference tracking, constructor ownership, skipped save, Burgers and documentation regression tests pass. The package also passes the tests for its new decision to drop direct 0.4 support. Two independent cases still destroy stored results, one during the documented 0.6 rehash and one while saving distinct inputs directly to a fresh 0.7 store.

## Findings in this change

1. **Critical — ordinary rehash can delete a different run before moving it.** At `src/DataManagement.jl:229`, the loop moves each source directly to its final name with forced replacement. I saved fields 10 and 20 with 0.6.3 for the strings `hello` and `"hello"` (the second includes the quote characters). I assigned both filenames the same timestamp prefix to model two jobs writing in the same millisecond. Both were independently loadable. In format 2, the destination of the first run is the still-occupied source of the second. Default `rehash_sim_data()` reduced two files to one, kept field 10 and marked the folder current. Plan all source/destination pairs, detect conflicts and stage overlapping moves before replacing anything. Test with both payloads and the same timestamp. [Upgrade output](2026-11-23-v0.7.0-codex-evidence/upgrade.txt)
2. **Critical — a valid parameter key can overwrite an unrelated result in a fresh store.** At `src/Serialization.jl:447`, keys are written verbatim into the hash input. The two pairs `:a => "label", :b => 2` produce the same text as the single pair `Symbol("a => \"label\", b") => 2`. At `src/IOUtils.jl:616` the overwrite guard compares a second calculation of the same hash. I saved field 20 for the first dictionary and field 10 for the second with `overwrite=true`. In 0.7 the first dictionary then returned 10. In 0.6.3 the same calls preserved two files and field 20. Encode dictionary keys and values unambiguously and compare the normalized stored parameters before replacing a file. [0.7 output](2026-11-23-v0.7.0-codex-evidence/current.txt) · [0.6.3 control](2026-11-23-v0.7.0-codex-evidence/previous.txt)
3. **Major — the default save directory locks itself after the first result.** At `src/IOUtils.jl:190` the format marker is written only when the data directory already exists. The first save creates that directory later, at line 621. Starting Julia in an empty directory and saving two numeric runs successively worked on 0.6.3. On 0.7 the second save demanded migration of the file 0.7 had just created. Create the directory before recording the format on the first write. Explicitly calling `set_save_path!` first also avoids the problem. [Version comparison](2026-11-23-v0.7.0-codex-evidence/README.md)
4. **Major — keeping old filenames turns them into false cache hits.** At `src/DataManagement.jl:182`, `rehash_sim_data(delete_old=false)` certifies the folder as current while it still contains format-1 filenames. At `src/IOUtils.jl:156`, current-folder reads trust those filenames. I seeded a 0.6.3 store with just the quoted string `"hello"` and field 20. After rehashing with copies, querying the never-computed plain string `hello` returned the quoted parameter and its field 20. Keep the old copies outside the active index or continue validating their stored parameters. [Upgrade output](2026-11-23-v0.7.0-codex-evidence/upgrade.txt)
5. **Major — a failed rehash still enables writes.** At `src/DataManagement.jl:218` an unreadable file returns the same result as a successful no-op. Line 182 then records format 2. I truncated a copy of a 0.6.3 file before rehashing and restored its intact bytes to its original name afterwards. The folder had already been marked current. A normal save created a second file for the same parameters and returned field 99 in place of the restored field 10. Distinguish a failed operation from an unchanged file and publish the marker only after every relevant file is verified. [Upgrade output](2026-11-23-v0.7.0-codex-evidence/upgrade.txt)
6. **Major — the documented 0.4 upgrade path can hide a user's metadata.** `docs/src/data.md:116` refers users to PDEStudioCore 0.6. Its 0.6.3 release already had the reserved-key defect recorded in the previous review. I added `evaluated_reference = "laboratory calibration"` to a copy of the genuine 0.4 fixture. After upgrading it with 0.6.3 and rehashing with 0.7, its dataset metadata lacked that value. The identical procedure using 0.6.2 retained it. This finding concerns the newly published upgrade instructions. Document the verified 0.6.2 path for affected files and recommend verifying metadata on a copy before replacing the original. [0.6.3 route](2026-11-23-v0.7.0-codex-evidence/upgrade.txt) · [0.6.2 control](2026-11-23-v0.7.0-codex-evidence/upgrade-control.txt)
7. **Minor — the batch counts a file missing its solution as a cache hit.** At `src/IOUtils.jl:790`, the format number suffices for `_is_current_file`. I removed only the `raw` entry from an otherwise current file. The 0.7 batch reported one cached task, zero reruns and still had no solution. Version 0.6.3 reported the run missing and restored the solution. Check the required dataset entries alongside the version. [Comparison output](2026-11-23-v0.7.0-codex-evidence/missing-raw.txt)
8. **Minor — loading a conversion modifies a folder documented as read-only.** At `src/IOUtils.jl:740`, with conversion caching enabled, `load_sim_data(p, :lagrangian)` wrote `conv_L` into an unmarked 0.6.3 Eulerian file with numeric parameters. Its SHA-256 changed before any rehash. The Eulerian cache write at line 728 uses the same helper. Serve the conversion in memory until the folder is writable. [Upgrade output](2026-11-23-v0.7.0-codex-evidence/upgrade.txt)

## Outside this change

- **Critical — the value `nothing` and its type `Nothing` overwrite one another.** At `src/Serialization.jl:39` and `src/Serialization.jl:452`, these distinct normalized parameters have the same printed representation. Saving fields 30 and 40 under those inputs left the first input returning 40 on both releases. Include the distinction between values and types in cache identity. [0.7 output](2026-11-23-v0.7.0-codex-evidence/current.txt) · [0.6.3 output](2026-11-23-v0.7.0-codex-evidence/previous.txt)
- **Major — Float16 grid spacing still overflows before the widened scatter calculation.** At `src/ConversionUtils.jl:121`, subtracting Float16 bounds −40000 and 40000 overflows even though the spacing of a three-node grid is representable. Both versions raised an `InexactError` inside conversion. The earlier 0-to-256 case passes on 0.7. Widen before subtracting the bounds and calculating spacing. [Version comparison](2026-11-23-v0.7.0-codex-evidence/README.md)
