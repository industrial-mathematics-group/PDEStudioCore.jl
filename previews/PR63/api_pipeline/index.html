API Reference: Configuration, Storage and Pipeline

Simulation configurations, parameter normalisation and identity, the data store and the pipeline. Datasets and statistics are on the previous page.

PDEStudioCore.SimulationConfig — Type
SimulationConfig(shared, methods = Dict(), defaults = all methods;
                 varied = Dict(), reference = nothing, postprocess = nothing, sources = String[])

Builds a SimulationConfig, converting loosely typed dictionaries (string or symbol keys) into ParamDict/MethodDict/VariedDict. Without methods, every run uses the shared parameters only. Functions are referenced by name (resolved in get_target_module).

source
PDEStudioCore.SimulationConfig — Type
SimulationConfig

Blueprint of a batch of simulation runs.

Fields

  • shared::ParamDict: baseline parameters of every run (usually contains :sim_func_name).
  • methods::MethodDict: per-method parameter overrides (:ignore => [...] drops shared keys).
  • defaults::Vector{Symbol}: the methods run_all_simulations executes.
  • varied::VariedDict: the parameter sweep (Cartesian product).
  • reference::Union{Symbol, Nothing}: name of a reference factory params -> (x -> u_exact).
  • postprocess::Union{Symbol, Nothing}: name of a function data -> Bool run on every dataset after the statistics (return true to save the modified data; the data itself is saved either way).
  • sources::Vector{String}: files included into the target module before running, in this order: helper files (a set, each defining its own names) and, as the last entry, the file that builds the configuration.

PDEStudioCore.resolve_dynamic_function — Function
resolve_dynamic_function(name, provided = nothing)

Looks up the function called name (a Symbol or String) in the target module (see set_target_module!), then among the solvers and references of the built-in examples (PDEStudioCore.Examples). A function passed as provided (or as name) is returned directly. Returns nothing (with a warning) if the name cannot be resolved.

Only names the target module (or one of its submodules) defines itself are accepted: names it merely imports (exports of Base, of PDEStudioCore or of other packages) are not, so a configuration file cannot run e.g. delete_sim_data or rm as its reference or solver. Define a wrapper in the target module to use such a function.

PDEStudioCore.calculate_hash — Method
calculate_hash(params::AbstractDict)

SHA-256 hash (hex string) of the normalised parameters (get_clean_params), the name of their data file (<save path>/data/<hash>.jld2). It digests a canonical encoding of the parameters: a header naming the hash format, then every value tagged with its kind (string, symbol, number with its type, container with its type and size, …) and every text prefixed by its length, keys sorted. Distinct normalised parameters therefore have distinct encodings (true and 1, "1" and 1, nothing and Nothing, [1 2] and [1, 2] differ) and, up to SHA-256 collisions, distinct hashes. Hash format 4 (PDEStudioCore 0.8); data of earlier versions is brought in with import_sim_data.

PDEStudioCore.param_identity — Function
param_identity(x) -> NamedTuple

What identifies a value of a custom type when it is part of a run's parameters: a NamedTuple (plain identifiers as names) of data (numbers, strings, symbols, tuples, arrays, dictionaries, types, and values of types that declare their own identity). Only this is stored and hashed; the other fields of the value are never looked at. Define it for every type whose values appear in parameters; a value of a type without it is refused (as are functions), so nothing that can't be compared reliably (functions, caches, derived fields) decides which run is which. For types whose fields are all data, @param_struct declares all fields at once.

# without its functions (is_interior, get_tag) and derived fields (volume)
PDEStudioCore.param_identity(d::GeometricDomain) =
    (; label = d.label, mins = d.mins, maxs = d.maxs, is_periodic = d.is_periodic, bc_map = d.bc_map, shape = d.shape)

It is stored as TypeName(key=value, …); see "What identifies a parameter value" in the manual.

PDEStudioCore.str2val — Method
str2val(val_str::AbstractString)

Inverse of val2str: parses literals and returns anything else as a (cleaned) string. Arbitrary code is never evaluated. Accepted are the values val2str writes: numbers, strings, symbols, characters, nothing, missing, types, tuples, typed or untyped vectors, reshape(T[...], dims), Dict{K, V}(...), Val{...}() and static arrays (SA{T}[...]); arithmetic on numbers such as 2π, 1/3 or sqrt(2); and a range as the whole value (1:10, 0:0.1:1).

Types come from an allowlist (the number types, including Rational, Complex, Irrational and the abstract ones, text, Tuple/NTuple, Vector/Matrix/Array, Dict, Pair, Val, Union, Type, DataType, UnionAll, Function, Nothing, Missing, Any and the static arrays of StaticArrays); other names stay strings. Values beyond the size limits are returned as strings too: more than 10^6 elements in total, exact numbers with more than 2^20 bits (BigFloats: exponents), types of a size above 1024 (parameters, nested ones and static array elements counted), more than 16 array dimensions, more than 32 levels of nesting, more than 1024 tokens between separators (,, ;) along the open brackets, keywords (begin, if, …) and assignments outside of Symbols such as :begin or :~, macro calls, ranges of BigInts or BigFloats with more than 2^24 bits in total, and functions such as sin or sqrt of a BigInt, BigFloat or Rational{BigInt}.

source
PDEStudioCore.val2str — Method
val2str(v; top_level::Bool = true)

Converts a value into a Julia-literal-like string (the basis of parameter normalisation). Top-level strings are written unquoted (unless their text could be read as something else, see below), strings inside containers are quoted, functions become "Closure" (parameters refuse them), enum values are written as TypeName.value and custom structs as TypeName(field=value, ...) from what identifies them (param_identity; a struct with an empty identity as its type with its parameters, e.g. Limiter{:minmod}). Type names are written without module prefixes, so the text doesn't depend on what the session loaded with using.

PDEStudioCore.@param_struct — Macro
@param_struct T
@param_struct struct T … end

Declares that every stored field of the struct T is part of what identifies its values in parameters (its param_identity is the NamedTuple of all fields): for types whose fields are all data, such as boundary conditions or shapes. Written in front of a struct definition, it defines the struct, too.

@param_struct struct Wall <: AbstractBC
    id::Int
end
@param_struct Limiter   # an existing type (here a tag without fields: identified by its type parameters)

PDEStudioCore.save_sim_data — Method
save_sim_data(sim_data::AbstractSimData; overwrite = false, verbose = true, metadata = Dict())

Saves the dataset under the hash of its (normalised) parameters, <save path>/data/<hash>.jld2, and returns the file path. The data stored for these parameters is only replaced when overwrite = true (which also drops stale conversion caches); a file at that name that holds other parameters, or whose parameters can't be read, is never replaced (an error). Neither is a symbolic link at that name: the store keeps no links, it neither writes through them nor replaces them. Writes are atomic: data is written to a temporary file that is then renamed into place. The dataset's metadata field is saved with it; metadata entries given here are added to it first. The metadata saved is the dataset's: new data gets a new provenance (:provenance) and has no :sources or :postprocessed (the stored metadata is replaced); the data stored for its parameters saved again (e.g. after add_stat!, or recomputed) takes the pipeline's entries of the stored metadata it doesn't have (:postprocessed only if the data still has the stored statistics). An entry removed from metadata stays removed. sim_data.params is replaced by its normalised form (see get_clean_params), as stored in the file.

PDEStudioCore.find_sim_data — Function
find_sim_data(match_params = Dict(); io = stdout, verbose = true)

Lists the data files of the runs whose stored parameters contain all the given key-value pairs, i.e. any subset of a run's parameters (keys may be strings or symbols; an empty filter lists every run). Values are compared as the hash tells them apart: 1 matches neither true nor 1.0. Only the lightweight params metadata is read. Prints one line per file (most recently written first) with the parameters that were not part of the filter, and returns the file paths. Files that aren't part of the store (see tidy_sim_data) aren't listed.

julia> find_sim_data(Dict("N" => 100));
2 data files with N = 100:
  3f9a51c0….jld2   cfl = 0.5, scheme = upwind, sim_func_name = :advection_solver_1d
  b02c7e14….jld2   cfl = 0.5, scheme = lax_friedrichs, sim_func_name = :advection_solver_1d

PDEStudioCore.import_sim_data — Method
import_sim_data(source; filter_pairs = nothing, remove_keys = Symbol[]) -> Vector{Pair{String, String}}

Copies runs into the store, the data folder of the current save path: the .jld2 file source, or every .jld2 file below the directory source (e.g. the data folder of an earlier PDEStudioCore version, of another save path or of another machine). Each run is stored under the hash of its parameters, as data/<hash>.jld2 (calculate_hash). The source must lie outside the data folder (and not contain it); it is only read.

Each selected source file is copied next to its destination, and that copy is checked before it is renamed into place: it must hold a dataset ("raw") whose parameters, kind and shape are those stored in the file, in the file format of PDEStudioCore 0.5 and later. Files that fail (can't be read, no dataset, written by PDEStudioCore 0.4, …) are reported and skipped. Every copy is written atomically, so an interrupted import is simply run again.

A run that is stored already is skipped. Nothing at a destination is ever replaced: a stored file of the parameters that isn't a usable run (e.g. without its dataset), a file of other parameters or one whose parameters can't be read, and a symbolic link are reported (move or delete them, then import again). Of several source files of the same parameters the first (by path) is imported, the others are reported.

Keywords

  • filter_pairs: only import runs whose stored parameters contain these exact pairs (compared as the hash tells values apart: 1 matches neither true nor 1.0).
  • remove_keys: parameter keys that didn't affect the result (e.g. one that no longer exists), dropped from the parameters. Otherwise the run is copied as it is: its data, statistics, and evaluation and post-processing records. To change a parameter that matters, run the solver again.

Returns the source => destination pairs of the runs it copied.

PDEStudioCore.sim_data_table — Function
sim_data_table(match_params = Dict()) -> DataFrame

One row per stored run whose parameters contain all pairs of match_params (as find_sim_data), most recently written first: file, created (when the data was made, from its provenance), size_mb, kind (:eulerian / :lagrangian), shape, format_version, stats (the available statistics), postprocessed (the names of the post-processors that ran, or missing), wall_time (seconds the solver took, if recorded), solver, then one column per parameter (missing where a run doesn't have it; a parameter named like one of the columns before gets the column param_<name>, with more param_ prefixes if that is a parameter, too). Only the lightweight entries of each file are read.

PDEStudioCore.tidy_sim_data — Method
tidy_sim_data(; dry_run = false, min_tmp_age = 3600) -> (temp_files, foreign)

Removes the temporary files of writes that never finished (a process killed while writing) from the data folder, if they are older than min_tmp_age seconds (a running write keeps its temporary file younger), and lists the files there that aren't part of the store: .jld2 files under other names than <hash>.jld2 (e.g. data of earlier versions or copies), files whose stored parameters have another hash than their name, files whose parameters can't be read or aren't valid parameters of this version, and symbolic links (the store keeps none). Lookups never use them, and they are never deleted here: move them out of the data folder and bring their runs into the store with import_sim_data.

Returns the paths of the temporary files it removed (with dry_run = true: would remove) and of the foreign files.

PDEStudioCore.RunSummary — Type
RunSummary

What run_all_simulations did (or, with dry_run = true, would do), shown as a short report:

  • tasks: the parameter sets of the configuration;
  • ran, cached, empty (the solver returned nothing), failed (params => error message): pass 1;
  • changed: stored results made with other source code (other contents of the source files, or another version of the solver's package), kept (on_changed_sources = :warn) or recomputed (:recompute); empty with :ignore;
  • stats, postprocessing: counts per outcome (:ran, :cached / :skipped, :outdated (post-processed by another version of the post-processor, see run_all_simulations), :failed, :missing, :not_run (the solver failed or returned nothing in pass 1: data stored before is left as it is)), and stats_failed, postprocessing_failed (params => error message);
  • files: the data file of each task (in the order of tasks), nothing where nothing usable is stored. After a run, the files holding the results; after a dry run, the files stored now, i.e. the data the configuration needs that is there already (e.g. to copy it with its configuration: filter(!isnothing, s.files));
  • elapsed: seconds; dry_run: whether nothing was run.

PDEStudioCore.generate_method_tasks — Method
generate_method_tasks(base_params, active_keys, active_values; ignore_keys = Symbol[])

Expands one method's parameters over the Cartesian product of active_values. Keys of the form :Ns__x/:Ns__1 (__y/__2, __z/__3, __<n>) set one entry of the tuple parameter :Ns; :Ns__xy (__xz, __yz, __xyz) sets several entries and :Ns__all every entry of the tuple to the same swept value (the result is a Tuple; entries past its end are added, gaps filled with 0.0). A key that is itself a parameter of base_params (e.g. :dt__1) is an ordinary key. A key joining parameters with & (Symbol("Grid_Ns__1&IC_cell"), see joint_sweep) sets all of them from a tuple of values, as one dimension of the product. Varied keys (or parameters of a joint key) that are absent from base_params (or ignored) are not applied to this method. Throws an ArgumentError if a suffix key addresses a parameter that is not a tuple or vector, or if a value of a joint key is not a tuple with a value for each of its parameters. Returns (tasks, grid_indices).

PDEStudioCore.joint_sweep — Method
joint_sweep(key => values, key => values, ...) -> Pair

A sweep of several parameters together (zipped, not a Cartesian product): the i-th run sets every parameter to its i-th value, e.g. a grid size with a cell width that follows it:

Ns = [40, 80, 160]
create_varied_dict(joint_sweep(:Grid_Ns__1 => Ns, :IC_cell => 6 ./ Ns), :PDE_epsilon => [1e-2, 1e-3])

Returns the entry for a VariedDict: a key naming the parameters joined by & (Symbol("Grid_Ns__1&IC_cell"); each may address tuple entries, see generate_method_tasks) with tuples of their values ([(40, 0.15), (80, 0.075), (160, 0.0375)]), so it is stored and written like any other sweep. A run has the same parameters (and hash) as a run of a configuration with these values set, so stored results are found again. The other swept parameters form the Cartesian product with the joint sweep as one dimension.

PDEStudioCore.run_all_simulations — Method
run_all_simulations(config::SimulationConfig; force_overwrite = false, calculate_stats = false,
                    force_stats = false, post_process = true, force_postprocess = false, parallel = false,
                    load_sources = true, on_changed_sources = :warn, dry_run = false) -> RunSummary

Runs the complete pipeline for a SimulationConfig and returns a RunSummary:

  1. includes config.sources into the target module (with load_sources = false the caller has done that itself, e.g. PDEStudio, which runs the source copies bundled with an export in place of their originals; their digests are stored either way),
  2. runs every task of generate_tasks whose data is not on disk yet (all of them with force_overwrite), in parallel over Julia threads with parallel = true. Stored results made with other source code (other contents of the source files, or another version of the solver's package) are handled by on_changed_sources: :warn keeps them and warns (once per session for the same results and code; the summary lists them on every run), :recompute runs them again, :ignore keeps them silently,
  3. with calculate_stats = true, evaluates missing statistics using the reference factory config.reference (params -> (x -> u_exact)); statistics that were dropped earlier for lack of a reference are evaluated again once a reference is configured, and all of them when another reference is configured. Statistics evaluated with the same reference whose code changed (the file defining it, or its package's version) are handled by on_changed_sources like solver results: :warn keeps them and reports them as :outdated, :recompute evaluates them again, :ignore only looks at the package version. The statistics of a file belong to one reference: if some are missing (e.g. newly registered ones), all of them are evaluated with the current reference and reported as :refreshed. force_stats = true recomputes every registered statistic without rerunning the simulations,
  4. with post_process = true, calls config.postprocess(data) for every dataset it hasn't post-processed yet and saves the data again when it returns true. A post-processor adds statistics (add_stat!) and metadata; one that changed the data's parameters or its solution fails and nothing is saved (a different result belongs into the solver). Each file records the post-processor that ran (its name, the source files of the run and its package's version), so it runs once per dataset and post-processor: on new data, and for a post-processor of another name. Data post-processed by another version of it (other source files or package version; with on_changed_sources = :ignore only another package version) is kept and reported as :outdated with a warning; force_postprocess = true runs it on every dataset, also on data it has processed already, so a post-processor should be idempotent (files of earlier versions have no record: the first run post-processes them).

With dry_run = true no solver, statistic or post-processor runs and nothing is written (the sources are still included): the summary lists what would run, and its files the data files the configuration needs that are stored already (nothing for those that would be computed), e.g. to copy them together with the configuration. Failures of individual tasks are logged, listed in the summary and do not abort the batch.

source
PDEStudioCore.run_smart_simulation — Method
run_smart_simulation(sim_func, params; force_overwrite = false, metadata = Dict())

Runs sim_func(params) unless a dataset for params already exists (then returns NoSimData()). The solver receives a deep copy of the parameters (what it changes, also inside arrays, changes neither params nor the parameters the result is stored under); the result is always stored under the task parameters so it can be found again. Its metadata (which the solver may fill) is saved with it, plus metadata given here and :provenance (versions, host, git commit, the solver and the seconds it took; see sim_data_table); a post-processing record of earlier data is dropped. Returns the produced data (or NoSimData()).
